# Вход в проект sf

## Обычная работа с CLI

При использовании фабрики **не открывайте `doc/tools/arch/**/*.py`**. Получайте сведения о командах из [arch-cli](doc/skills/arch-cli/SKILL.md), точечного `--help` и фактического результата. Это касается чтения через файловые инструменты, shell, поиск по коду и граф. Сначала попробуйте задокументированную команду. Если интерфейс расходится с результатом, запишите точный вызов и ошибку.

Исходники CLI нужны, когда запрос прямо меняет CLI или требует диагностики воспроизводимого расхождения. В этом случае найдите один обработчик или связанный тест по имени и прочитайте относящийся к делу диапазон строк.

## Маршрут

- Вход по ключу задачи — [doc/AGENTS.md](doc/AGENTS.md), затем краткий `task diagnose <key> --json --brief` и нужные файлы из `refs`.
- Запрос «подготовься к выполнению» ведёт к плану и проверке готовности. Изменения начинаются после поручения на реализацию. [go-to-task](doc/skills/go-to-task/SKILL.md)
- Постановка задачи — [create-task](doc/skills/create-task/SKILL.md). Выполнение и приёмка — [go-to-task](doc/skills/go-to-task/SKILL.md).
- Поиск и аудит прошлых сессий Kilo Code — [kilo-session-audit](doc/skills/kilo-session-audit/SKILL.md).
- Поиск проектных контрактов — [architecture-read](doc/skills/architecture-read/SKILL.md). Исследование практик — [MOC базы знаний](data/README.md).

Для чтения и проверки в Kilo доступен режим `factory-operator`. Для реализации самого CLI используйте рабочий режим с правом читать целевой исходник.
