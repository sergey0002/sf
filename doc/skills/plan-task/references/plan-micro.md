# Шаблон плана: `micro`

Для `complexity: low`, до 2 часов, 1–2 файла, один AC, без изменения контракта. Лимит плана — 60 непустых строк; больше — переходите на `standard`.

## Что обязательно

- Маркер `<!-- plan-tier: micro -->` первой строкой.
- Заголовки, содержащие `Приёмка` и `Проверка`.
- Один `CASE` с независимым оракулом на каждый AC.
- Точная команда проверки и одна строка отката.

## Шаблон

```markdown
<!-- plan-tier: micro -->
# <KEY>: <что меняем>

## Изменение

- Файл: `<точный путь>`
- Сейчас: <наблюдаемый факт>
- После: <наблюдаемый факт>
- Не входит: <граница>

## Приёмка

| CASE | AC | Дано | Действие | Ожидание и проверка |
|---|---|---|---|---|
| CASE-1 | AC-1 | <fixture> | `<команда>` | <код выхода / поле / байты> |

## Проверка

```bash
<целевая команда>
arch validate --brief
```

- Ожидание: exit 0, <наблюдаемый результат>.
- Откат: <одно действие, например revert коммита или удаление файла>.
```

## Когда micro недостаточен

Повышайте tier, если появилось любое из:

- больше одного AC или больше двух файлов;
- публичный контракт, формат хранения, миграция;
- отказной или совместимый сценарий, который нужно описать;
- оценка выше 2 часов.
