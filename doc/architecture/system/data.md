# Границы данных и записей

| Запись | Формат/статус | Власть и жизненный цикл |
|--------|--------------|------------------------|
| Корневой манифест | Один файл Markdown в корне проекта | Единственный высокоуровневый источник для этого scaffold; не копировать в энциклопедию/подпапки |
| Повествование архитектуры | Markdown с маленьким YAML frontmatter | Канонические документы; статус ревью контролирует, является ли принятым/текущим |
| Индекс архитектуры | Сгенерированный JSON, валидированный по схеме | Только производные метаданные; regenerieren, никогда не править вручную |
| Схемы архитектуры | JSON Schema Draft 2020-12 | Maschinenские контракты; иллюстративные до утверждения |
| Канонический ввод задачи | Один версионированный `task.json` | Единственный ввод задачи; требуется четырёхзначный номер задачи и ключ, производный от источника; происхождение источника сохраняется; неизменен после начала выполнения |
| План/результат этапа | Markdown/структурированные записи (точное разделение нерешено) | Дополняет ввод задачи; ссылки на diff/доказательства |
| Доказательства верификации | Структурированные ссылки + сохранённый вывод команды/артефакты | Должно идентифицировать точное состояние кода; без доказательств нет утверждения о пройденном |
| ADR/решение | Фокусированная запись Markdown с явным статусом, контекстом/вариантами/последствиями | Принятое решение должно быть связано с затронутыми каноническими документами |
| Схемы API/событий | OpenAPI/AsyncAPI только если у системы есть соответствующие интерфейсы | Никакой контракт интерфейса не подразумевается этой только-документационной выкладкой |
| Очередь/вывод будущего сканера | Приватно для отдельного будущего производителя | Не должно стать требуемым форматом документации архитектуры |

## Политика формата

Используйте Markdown для повествования, читаемого человеком/агентом, и решений; JSON Schema для структурированных контрактов; JSON для сгенерированного индекса и машинных записей; простые логи/отчёты для захваченных доказательств с метаданными. Не выбирайте YAML как общий формат обмена данными. Табличный CSV/XLSX не является канонической архитектурой; диаграммы должны быть версионным текстом (например, Mermaid/эскизы контекста/контейнера C4), когда добавляются. Бинарные экспорты — производные, не авторитетные.
