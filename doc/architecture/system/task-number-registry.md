# Политика выделения и реестра номеров задач

## Политика (из корневого манифеста)

- У каждой задачи ровно четыре десятичные цифры (`0000`–`9999`) как `task_number`.
- `task_key` детерминирован:
  - Jira: только чистое число (`1234`), без префикса.
  - Ввод пользователя (`source.type: ui`): `UI-` + число (`UI-1234`).
  - Каждый другой источник: явный зарегистрированный/настроенный префикс + число (`GH-1234`).
- Номера уникальны в пределах семейства источника (UI, Jira, конкретный префикс).
- CLI выводит и валидирует ключи, а для `source: ui` выделяет следующий свободный номер.

## Хранение реестра

Реестр — машинные данные, а не Markdown-таблица. Единственный файл:

```
doc/config/task-registry.json
```

Схема:

```json
{
  "schema_version": 1,
  "tasks": [
    {
      "task_key": "UI-0001",
      "task_number": "0001",
      "source": "ui",
      "title": null,
      "created_at": "2026-11-22T00:00:00Z"
    }
  ]
}
```

Реестр ведётся **только CLI**:

- `arch task new --title "<title>"` — для чата: выделяет следующий UI-номер, создаёт задачу и добавляет запись.
- `arch task init <key> --title "<title>"` — для известного ключа: создаёт задачу и добавляет запись.
- `arch task-key --source ui --next` — предпросмотр следующего ключа без записи.
- `arch task registry --json` — чтение реестра; `arch task registry init` — создание пустого реестра; `arch task registry add <key>` — регистрация существующей карточки.
- `arch task registry check` — read-only сверка реестра с каталогами задач; exit 1 при расхождении.
- `arch task registry sync [--prune]` — автоматически добавляет карточки, которых нет в реестре; `--prune` удаляет записи без каталога.

Агент и человек не читают и не редактируют этот JSON вручную. Запись обновляется атомарно под блокировкой каталога конфигурации; повреждённый или конфликтующий реестр останавливает создание задачи.

## Контроль и синхронизация

- `task registry check` сравнивает реестр с верхнеуровневыми каталогами `doc/tasks/<key>/task.json` и сообщает: `missing_in_registry`, `missing_on_disk`, `number_mismatch`. Запись не меняется; это проверка локального gate.
- `task registry sync` формирует недостающие записи из каталогов (title и номер берутся из `task.json`), не трогая существующие. `--prune` дополнительно удаляет записи, чей каталог исчез.
- `number_mismatch` (номер в `task.json` не совпадает с ключом каталога) останавливает `sync`: сначала исправьте карточку, затем повторите.
- Синхронизация не сканирует `subtasks/` и служебные каталоги; она работает только с верхним уровнем `roots.tasks`.

## Выделение и коллизии

- Следующий UI-номер — максимум по реестру плюс один; каталоги задач не сканируются.
- `task-key --next` ничего не резервирует. Резервированием считается только запись, созданная вместе с задачей.
- Jira и внешние источники получают номер из своего трекера; автоматическое выделение для них не выполняется.
- Коллизию ключа или номера останавливает CLI; повторная запись того же ключа идемпотентна, другой номер для существующего ключа — ошибка.

## Текущие назначения

Список назначений не дублируется в этом документе. Источник истины — `arch task registry --json`.

## Правило остановки

Перед присвоением нового номера подтвердите тип источника и префикс с владельцем. Не выдумывайте и не угадывайте префикс. Если источник не Jira, не UI и не имеет настроенного префикса, остановитесь и спросите.
