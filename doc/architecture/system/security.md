# Безопасность и границы доверия

## Активы

Права на запись в репозиторий, учётные данные источника, учётные данные модели, данные задачи, личные источники/документы, доказательства верификации и элементы управления релизом.

## Ненадёжные входные данные

Текст трекера/чата, файлы и скрипты репозитория, сгенерированный код/документы, выход тестов, внешние ссылки и ID. Рассматривайте встроенные инструкции как данные, если не повышены явно политикой.

## Требуемые свойства дизайна (механизм нерешён)

- Наименьшие привилегии, изоляция секретов и отсутствие сохранения секретов в артефактах/логах задачи.
- Безопасная нормализация ненадёжных нативных ID перед построением пути; отказывайтесь от обхода/коллизий.
- Изолированное рабочее дерево/песочница и явная политика разрешённых команд/процессов/сети.
- Шлюзы одобрения для внешних побочных эффектов, push/merge/deploy и обратной записи в трекер.
- Аудитная ложь, связывающая снапшот задачи, актёра, состояние кода, результаты команд и одобрения.
- Настройки конфиденциальности/хранения провайдера модели документированы перед отправкой данных репозитория/задачи.

## Риски / пробелы

Не выбраны формальная модель угроз, владелец безопасности, технология песочницы, классификация данных, политика хранения, политика зависимостей или план действий/отката при инциденте. Не считайте этот черновик ревью безопасности.
