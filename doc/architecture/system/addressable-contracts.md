# Адресуемые контракты документации

## Назначение

Дать агенту воспроизводимый маршрут от вопроса или задачи до применимого раздела документации, связанных проверок и последствий изменения. Вместо перебора файлов и чтения документов целиком CLI адресует раздел, ограничивает выдачу бюджетом и показывает объявленные связи. Смысловые решения — применимость правила, авторитет источника, достаточность evidence и приёмка — остаются за агентом и владельцем.

## Требования

### Стабильные якоря {#anchors}

- Раздел адресуется как `DOC-ID#section-id`.
- Явный якорь объявляется суффиксом заголовка `{#section-id}` и переживает перенос файла и переименование заголовка.
- Заголовок без явного якоря получает детерминированный slug. Slug-якорь нестабилен: он переживает правку текста, но не переименование заголовка. Совместимость со старыми slug-ссылками сохраняется.
- Заголовки внутри fenced code block не являются разделами.
- Повторяющийся якорь делает ссылку неоднозначной; CLI не выбирает раздел по порядку.

### Ограниченное чтение {#read}

```
arch docs read <DOC-ID#section-id> [--max-bytes N] [--json]
```

- Возвращает `doc_id`, проект-относительный `path`, `anchor`, `anchor_kind`, `stable`, `title`, `heading_path`, диапазон `line_start`/`line_end`, `bytes`, SHA-256 исходного файла, `doc_status` и `content`.
- Раздел включает подразделы до следующего заголовка того же или более высокого уровня.
- `--max-bytes` ограничивает размер раздела. При превышении CLI возвращает `SECTION-TOO-LARGE` и не выдаёт частичный текст как полный контракт.
- Отсутствующий якорь даёт `SECTION-NOT-FOUND`, повторяющийся — `SECTION-AMBIGUOUS`, оба с exit 1. Ссылка без якоря — ошибка аргументов, exit 2.

### Поиск {#search}

```
arch docs search <query> [--scope product|reference|all] [--limit N] [--include-archived] [--json]
```

- Запрос разбивается на термы; совпасть должны все термы. Регистр не учитывается, поддерживаются кириллица и явные `aliases` из frontmatter.
- Порядок: точный ID или alias, вхождение в ID, заголовок, summary, заголовок раздела, тело. Равенство разрешается по `id`, пути и строке.
- `--scope product` ищет архитектурные документы; `reference` — только справочный корень; `all` — оба. `data/` никогда не попадает в выдачу по умолчанию.
- `superseded`, `deprecated` и `rejected` исключаются без `--include-archived`. Черновики включаются и маркируются статусом.
- Выдача содержит `id`, `source`, `type`, `title`, `status`, `path`, `anchor`, `line`, `match`, `score` и короткий `snippet`. Пустой результат — успех с `hits: []`.

### Проверка ссылок {#check-links}

```
arch docs check-links [--json]
```

- Проверяет локальные Markdown-ссылки: отсутствующий файл, выход за корень проекта, отсутствующий якорь в целевом или текущем документе.
- Ссылки внутри fenced code block не проверяются.
- Каждый инцидент содержит `code`, `source`, `line`, `target` и `anchor`. Наличие инцидентов даёт exit 1.

### Контекст задачи {#context}

```
arch docs context --task <key> [--case CASE-N] [--max-bytes N] [--since-snapshot FILE] [--json]
```

- Источники: `related_docs`, `project_context_refs`, `related_tests` карточки и `planned_checks` текущей стадии.
- Каждый элемент содержит `kind`, `ref`, причину включения `declared_by`, `state` и, где применимо, `authority`, `sha256`, `path` и диапазон якоря.
- `authority` различает `contract`, `adr`, `reference`, `document`, `file` и `test`. Наличие ссылки не доказывает выполнение проверки.
- Для кейса возвращаются `expected`, `covers`, текст AC из `acceptance_criteria` и `evidence` со состояниями `not_run`, `failed` или `passed`, а также `snapshot_state` (`current`, `stale`, `unknown`).
- `complete: false` означает пропущенный или неразрешённый источник, отсутствующий кейс, устаревший/конфликтующий документ либо усечение по бюджету. Это структурированный результат, а не пустой успех.
- `--since-snapshot` принимает предыдущую выдачу и возвращает только добавленные и изменённые элементы; удалённые перечисляются в `delta`.
- `--max-bytes` ограничивает машинную выдачу. При усечении CLI перечисляет `omitted` и ставит `complete: false`.

### Влияние изменений {#impact}

```
arch docs impact --since <git-revision> [--scope docs|all] [--json]
```

- Сравнивает указанную ревизию с текущим checkout, включая рабочие изменения. `--scope docs` (по умолчанию) ограничивает анализ архитектурными Markdown-документами.
- Для каждого изменённого документа показывает добавленные, изменённые и удалённые разделы по стабильному ключу якоря.
- `affected` перечисляет только объявленных потребителей: `related` документов, `related_docs` и `project_context_refs` задач, локальные ссылки на изменённый файл.
- Текстовое совпадение никогда не выдаётся за доказанное влияние. Изменённые документы без объявленных потребителей попадают в `unverified_coverage`.
- Неотслеживаемые файлы считаются добавленными. Git rename detection не выполняется; это указано в `notes`.

### Инварианты {#invariants}

- Источник текста — текущий checkout. Результаты привязаны к SHA-256 содержимого, поэтому незакоммиченные правки видны и различимы.
- CLI не выводит применимость, реализацию или одобрение из ранга, статуса либо наличия ссылки.
- Обычное чтение, поиск и анализ не пишут в репозиторий и не обращаются к сети.
- `data/` остаётся справочным корпусом и подключается только явным `--scope`.
- Существующие команды `list`, `show`, `docs tree`, `docs related` и их форматы сохраняются.

### Границы {#boundaries}

- Нет LLM, embeddings и внешних поисковых сервисов: поиск локальный и детерминированный.
- Нет автоматического исполнения команд, найденных в документах.
- Нет автоматического разрешения конфликтующих источников и утверждения правил.
- Массовая миграция Markdown не требуется: явные якоря добавляются только цитируемым разделам.
