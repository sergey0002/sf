# Нормализация входящих задач в `task.json`

## Назначение

Сохранить происхождение источника и создать один структурированный, валидный по схеме ввод задачи, который может безопасно привести к детерминированным операциям CLI и выполнению агентом.

## Область и исключения

В области: Jira, другие настроенные трекеры и ручной/чатовый приём. Эта спецификация не выбирает API трекера, ключ проекта, механизм аутентификации, итоговую JSON Schema, схему веток или модель.

## Требования

### Требование: сохранить идентичность и происхождение источника

Фабрика ДОЛЖНА сохранять тип источника, нативную идентичность/ссылку, доступную метаинформацию ревизии/снапшота и ссылки на вложения/комментарии для каждой нормализованной задачи.

#### Сценарий: задача трекера извлекается

- **КОГДА** настроенный адаптер источника извлекает задачу
- **ТОГДА** ввод задачи сохраняет идентичность источника и снапшот/происхождение, необходимые для идентификации того, что было прочитано

### Требование: task.json — единственный канонический ввод задачи

Фабрика ДОЛЖНА представлять все известные поля задачи, необходимые для детерминированных операций CLI и выполнения агентом, в `task.json` или явно参照ной версионированной конфигурации проекта.

#### Сценарий: задача нормализуется

- **КОГДА** приём завершается
- **ТОГДА** вход выполнения — `task.json`, а не отдельно отредактированный `task.md`

### Требование: неопределённость разрешается скиллом агента

Фабрика ДОЛЖНА оставлять семантическую интерпретацию, оценку полноты и уточнение скиллу агента, а не адаптеру источника/CLI.

#### Сценарий: поля источника неполные или конфликтуют

- **КОГДА** необходимо семантическое решение для нормализации задачи
- **ТОГДА** скилл просит уточнения или помечает разрешённое нерешённое поле; CLI не угадывает

## Идентичность задачи

Каждая задача имеет десятичное число задачи из четырёх цифр. Ключи Jira используют чистый номер; ввод пользователя использует тип источника `ui` и префикс `UI-`; остальные источники требуют явного префикса. Детерминированный инструмент ведёт JSON-реестр; для `source: ui` команда `task new` выделяет следующий свободный номер, создаёт задачу и добавляет запись. Глобальная уникальность между источниками остаётся блокером для продакшен-приёма.
