# Целостность архитектурной документации

## Назначение

Позволить агенту или ревьюеру обнаруживать и структурно валидировать архитектурную документацию без поручения CLI судить о смысле.

## Требования

### Требование: индекс генерируется из явных метаданных

Инструмент документации ДОЛЖЕН строить стабильный индекс из проверенного frontmatter и НЕ ДОЛЖЕН семантически классифицировать документы.

#### Сценарий: документы индексируются

- **КОГДА** запрашивается построение индекса
- **ТОГДА** записи включают стабильные ID/типы/пути и детерминированную упорядоченность

### Требование: некорректная структура сообщается точно

Инструмент документации ДОЛЖЕН сообщать ошибки схемы/frontmatter/ссылки/дубликата ID с файлом/путь и ненулевым кодом выхода.

#### Сценарий: документ некорректен

- **КОГДА** запускается `arch validate`
- **ТОГДА** он сообщает точный файл и поле/ссылку и не переписывает семантическое тело

### Требование: агент владеет релевантностью и смыслом

Инструмент документации ДОЛЖЕН предоставлять точные результаты `list`/`show`, но НЕ ДОЛЖЕН выбирать, какие документы семантически релевантны, или автоматически исправлять контент.

#### Сценарий: задача влияет на поведение проекта

- **КОГДА** агент выбирает документацию для ревью
- **ТОГДА** он использует контент/доказательства для выбора релевантных документов, а CLI выполняет только явные структурные проверки
