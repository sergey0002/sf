# Словарь программной фабрики

> Определения ниже обобщают только корневой манифест. Элемент, помеченный как нерешённый, не является окончательным техническим контрактом.

### Ввод задачи — `TERM-task-json`

- **Определение:** Версионированный, нормализованный JSON-ввод для одной задачи; единственный канонический ввод задачи для текущего ядра.
- **Синонимы:** `task.json`.
- **Избегайте:** Считать отдельно отредактированный `task.md` эквивалентным вводом.
- **Связано:** `ENT-task-input`, `CAP-task-intake`.

### Номер и ключ задачи — `TERM-task-key`

- **Определение:** У каждой задачи есть четырёхзначное десятичное `task_number` (`0000`–`9999`). `task_key` детерминирован: Jira использует только число (`1234`); ввод пользователя использует `UI-1234`; каждый другой источник использует явный зарегистрированный/настроенный префикс (`GH-1234` и т.д.).
- **Словарь источников:** `source.type: jira` означает Jira; `source.type: ui` означает запрос, введённый пользователем (пользовательский ввод), а не интеграцию UI. Остальные источники сохраняют свой тип источника и требуют префикс.
- **Граница:** CLI выводит/валидирует ключи, но никогда не выделяет номера. Выделение номеров, глобальная уникальность и миграция нерешены; дублирующие ключи должны останавливаться, а не перезаписываться.
- **Связано:** `ENT-task-input`, `FLOW-create-task`.

### Адаптер источника — `TERM-source-adapter`

- **Определение:** Детерминированный соединитель, извлекающий явные поля трекера/чата, сохраняющий происхождение источтора и сопоставляющий известные поля без семантической интерпретации.
- **Связано:** `DOM-task-intake`, `CAP-task-intake`.

### Скилл — `TERM-agent-skill`

- **Определение:** Инструкции рабочего процесса, ориентированные на агента, которые владеют семантической интерпретацией, уточняющими вопросами, выбором извлечения, планированием и архитектурным суждением.
- **Связано:** `doc/skills/`.

### Дельта архитектуры — `TERM-architecture-delta`

- **Определение:** Предложение задачи/этапа, описывающее минимальное семантическое изменение канонических документов архитектуры; не текущая истина до необходимого ревью/принятия.
- **Связано:** `ENT-stage-artifact`, `FLOW-document-session`.

### Этап — `TERM-task-stage`

- **Определение:** Ограниченная итерация работы задачи с собственным планом/контекстом/дельтой/ссылками на доказательства; точная схема этапа нерешена.
- **Связано:** `ENT-stage-artifact`.

### Доказательство верификации — `TERM-verification-evidence`

- **Определение:** Ссылки, проверяемые машиной/человеком, на точные команды, коды выхода, проверенное состояние кода и выходные артефакты. Самоотчёт агента сам по себе не является независимым доказательством.
- **Связано:** `ENT-verification-evidence`, `CAP-single-agent-execution`.

### Сканер документации кода — `TERM-future-code-scanner`

- **Определение:** Будущая отдельная программа, описанная в корневом манифесте, которая может проверять код и черновить архитектурную документацию, используя код-граф/MCP/скиллы/суб-агентов; не является частью текущего ядра фабрики.
- **Избегайте:** Выводить принятое бизнес-значение только из кода.
