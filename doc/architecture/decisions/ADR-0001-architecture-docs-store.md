# Хранилище архитектурной документации

## Контекст и проблема

Фабрике нужно одно версионируемое, читаемое агентом место для архитектурных знаний: границы, решения, возможности, сущности, потоки и точки зрения. Корневой манифест требует `task.json` как канонический ввод задачи и один корневой файл манифеста; он оставляет хранение документации открытым. Без принятого хранилища агенты не могут надёжно находить канонические архитектурные факты, а изменения не имеют проверки/управления версиями.

## Драйверы решения

- Поиск, ориентированный на агента: индекс primero, загружайте только релевантные документы, без полного дампа.
- Детерминированный CLI для структурных операций; семантические решения остаются за агентом/владельцем.
- Markdown как проверяемая, читаемая человеком/агентом повествовательная форма; без копирования машинных источников истины (OpenAPI, JSON schema, код).
- Без дублирования истины: один канонический репозиторий документов, отдельно от репозитория продукта.
- ISO 42010/arc42/C4 как чеклисты, не обязательные структуры папок.

## Рассмотренные варианты

1. **Один репозиторий документов Git с `.doc/architecture/`, Markdown + YAML frontmatter, сгенерированный `index.json`, CLI `arch.py`** (выбран).
2. Отдельная платформа документов / база знаний / вторая копия в каталогах продукта — отклонено (дублирование, нет одного источника истины).
3. Универсальный DSL или Markdown-внутри-JSON для всей архитектуры — отклонено (переусложнение, не ревьюируемо).
4. Обязательные все 12 разделов arc42 / все уровни C4 — отклонено (чеклист, не шаблон).

## Итог решения

Принят вариант 1. Каноническая архитектура живёт в `doc/architecture/` как Markdown с коротким YAML frontmatter. `index.json` — сгенерированные машинные метаданные, никогда не редактируются вручную. `arch.py` предоставляет только `list/show/index build/index check/validate`. Семантическая релевантность, планирование и архитектурное суждение остаются обязанностями агента. ADR живут в `doc/architecture/decisions/`.

## Последствия

- Положительные: версионируемо, ревьюируемо, diffable; агент может навигировать через индекс + прямые ссылки; CLI валидирует структуру без угадывания смысла.
- Отрицательные: требуется дисциплина ручной правки Markdown; нет автоматической семантической связи; нет встроенного сервиса поиска.
- Риски: устаревание документов, если проверка/обновление не принуждаются; смягчается метаданными `status` и шлюзами одобрения человеком.

## Подтверждение / как проверить

Запустите `arch validate` и `arch index check`; оба должны пройти. Каждый документ в `index.json` должен иметь соответствующую запись frontmatter с уникальным `id`.
