# Планирование рефакторинга

Возьмите карточку, `Правила проекта` из `architecture-context` и baseline из `analyze`. В плане привяжите сохраняемые точки входа и контракты к целевым проверкам. Задайте короткий рабочий срез и опишите требуемое согласование.

Для составной записи укажите состояние до и после каждой поддерживаемой границы прерывания. Отдельно проверьте повтор после записи результата, поздний конфликт, повреждённый журнал и конкурентного писателя, если он входит в контракт. Для отказа зафиксируйте ожидаемый exit code и сравнение дерева до и после. Для небольшого рефакторинга укажите только применимые проверки.

До перехода к `refactor` у каждого обязательного AC должен быть оракул, отличающий правильный результат от ошибочного. Начните с одного целевого теста опасного перехода.
