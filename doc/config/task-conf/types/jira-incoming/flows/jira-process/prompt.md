# Стартовый промпт flujo jira-process

Это стартовый промпт flujo `jira-process` для типа `jira-incoming`. Исполняется при начале работы над задачей этого типа и этого flujo.

## Назначение

Регламентирует, как работает агент с входящей задачей из Jira: от приёма task.json до закрытия задачи.

## Шаги процесса

### 1. Приём и валидация (intake)

- Прочитай `task.json` задачи.
- Убедись, что `source.type == "jira"`.
- Убедись, что `task_key` — bare four-digit number (например, `0427`), без префикса `UI-` или `GH-`.
- Запусти `arch task validate <task_key>`.
- Если валидация не прошла — остановись и исправь ошибки перед продолжением.

### 2. Планирование (plan)

- Составь `stage1/plan.md`: какие файлы будут изменены, какие подзадачи созданы, какие критерии приёмки.
- Укажи `allowed_files_modules` из `task.json` — изменения только в этих рамках.
- Получи approval на план от владельца задачи.

### 3. Реализация (implement)

- Внеси изменения только в рамках `allowed_files_modules`.
- Не 편ь `data/` как проектные файлы.
- Не создавай `task.md`.
- Создай подзадачи через `arch task decompose <task_key> --subtask-id NNNN --subtask-title "..."` если требуется декомпозиция.

### 4. Верификация (verify)

- Запусти `arch validate` и `arch docs paths --check`.
- Запусти тесты из `related_tests` или созданные новые.
- Подготовь `stage1/verification.json` с evidence.

### 5. Закрытие (close)

- Убедись, что все подзадачи имеют `phase: completed` (проверь через `arch task diagnose <task_key>`).
- Получи approval владельца.
- Закрой через `arch task close <task_key>`.

## Защитные правила

- CLI не аллоцирует `task_number` автоматически.
- CLI не принимает семантических решений за агента.
- task.json не перезаписывается задним числом без явного оформления в stage_history.
- Задача не закрывается, если есть незакрытые подзадачи.
