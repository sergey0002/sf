# Тип `subtask`

Лист работы внутри родительской задачи. Подзадача существует, когда у неё есть собственный наблюдаемый результат, `AC-N`, `CASE` с независимым оракулом и граница записи. Тип запрещает дальнейшую декомпозицию: если результату нужны свои дети, выберите конкретный тип (`feature`, `bugfix`, `refactor`, `docs`) или создайте отдельную задачу.

`task_type`, `flow`, `complexity` и `estimate_hours` выбирает агент. По умолчанию карточка создаётся как `subtask` без flow; конкретный flow берите из типа, который соответствует содержанию работы. Формат плана — по навыку [plan-task](../../../../../skills/plan-task/SKILL.md).

Используйте YAML типа для обязательных полей и политики подзадач, план — для оракулов и порядка. Источники, фиксация проверок и условия закрытия описаны в `doc/AGENTS.md` и `go-to-task`.
