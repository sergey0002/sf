Этот отчёт фиксирует состояние до исправлений. Результаты последующего выполнения и новый снимок приведены в [верификации стадии](../stage1/verification.json).

**Реализация 4/10. Процесс 5/10.** Kilo добавил загрузчик YAML и связал его с точкой входа CLI. Обычная раскладка работает поверх существующих артефактов, но чистый прогон выявил запись индекса в корень проекта, жёсткий путь к задачам и обход только `doc/` при проверке путей. ## Проверка требований

Проверки использовали абсолютный путь к текущему `doc/tools/arch/__main__.py`, `--root` временной fixture и рабочий каталог вне fixture. В каждом корне использованы минимальный документ `DOC_SAMPLE`, проектные схемы, task-conf и копия карточки `UI-0012` с детьми. В каждом запускались `list --json`, `show DOC_SAMPLE`, `index build`, `index check`, `validate --brief`, `docs paths --check` и `task diagnose UI-0012 --json --brief`. Для перенесённой и игнорируемой раскладок YAML выбирался через `--config` относительно `--root`. Третья fixture использовала `.gitignore` с `/private/`; её `git check-ignore` подтвердил игнорирование документа. Первые две fixture работали без Git.

Причины проверенных ошибок видны в реализации. `load_project_config` разрешает `roots.index` относительно проекта и делает его абсолютным. При сложении `architecture_root / absolute_index` правый абсолютный путь вытесняет левый. `get_allowed_paths()` заменяет неверный тип `allowed_paths` пустым списком, а вход CLI не проверяет его до `index build`. `validate_paths` обходит `root / "doc"`, а роутер задач использует `task_dir(project_config.root, key)` с зашитым `doc/tasks`. Публичный контракт конфигурации и правила запуска остаются рассинхронизированными. Оценка реализации учитывает рабочий вход, штатный прогон, частичную диагностику конфига и отказ ключевых сквозных сценариев.
