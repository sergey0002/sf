# UI-0026: адресуемые контракты продукта в Arch CLI

## Результат и порядок

1. `0001` (AC-1, AC-2, часть AC-4): создать общий резолвер разделов, компактную машинную выдачу поиска и проверку ссылок. Не подменять `index.json` поисковым кешем; если кеш появится, он производный, проверяемый и не выдаёт устаревшие результаты как актуальные.
2. `0002` (AC-3, AC-4; после `0001`): связать разделы с существующими `related_docs`, `project_context_refs`, AC/CASE и evidence по объявленным ссылкам. Согласовать границу с `UI-0019` до интеграции. Не блокировать адресацию и поиск ожиданием общего runtime стадии.
3. `0003` (AC-5; после `0001` и `0002`): размеченный пилот на закрытии задачи, справка, регрессия и сравнение с базовым маршрутом. Автоматически сверять документированный набор новых флагов с `--help`, проверять примеры на фикстурах; не исполнять произвольные Markdown-блоки. Перед итоговой проверкой выполнить `review-implementation` и `architecture-sync`.

## Проект интерфейса

- `arch docs read 'DOC-ID#section-id' --max-bytes N --json`: явные стабильные якоря только у цитируемых разделов; диапазон 1-based включительно, SHA-256 исходного файла, статус документа. Не считать заголовки внутри code fence секциями. При превышении лимита вернуть способ прочитать меньший диапазон; не выдавать частичный текст как полный контракт.
- `arch docs search QUERY --scope product --limit N --json`: локальное ранжирование «точный ID/явный алиас → заголовок → summary → тело», стабильное разрешение равенств; короткий фрагмент и путь заголовков. Черновик маркируется, архив и `data/` только явным выбором. Русский и английский термины и явные алиасы проверить в пилоте; без обещания общего семантического поиска.
- `arch docs context --task KEY --case CASE-N --max-bytes N [--since-snapshot FILE] --json`: компактные ссылки, причины и обязательные пробелы, текст только в пределах бюджета. Явно отличать исходный контракт, ADR, справочник и evidence; не считать наличие ссылки подтверждением выполнения. Возвращать хеши источников; для сравнения показать добавленные, изменённые и удалённые элементы. Не выполнять чтение из путей, переданных содержимым документов, за пределами разрешённых корней.
- `arch docs check-links --json`; `arch docs impact --since BASE --json`: проверять существование/единственность якорей. Для `impact` определить diff базы к текущему checkout, включая рабочие изменения выбранных отслеживаемых файлов; отсутствие связи не выдавать за отсутствие риска. Новые неотслеживаемые файлы, если не поддержаны, явно отметить как ограничение.
- Зафиксировать машинные коды ошибок, версию формата и семантику лимитов до реализации. Предлагаемый контракт: 0 при корректной выдаче (включая `hits: []`); 1 для неразрешимой/неоднозначной ссылки и `check-links` с инцидентом; 2 для неверных аргументов. Для `context` с пропусками вернуть структурированный результат с `complete: false`, а не пустой успех. Обычное чтение не меняет дерево и не требует открытия сети.

## Источники и ограничения

- Исходное наблюдение в чате: `docs tree`/`list` дают метаданные, а `show --help` не предлагает выбор раздела. Числа из предварительной оценки не считать измерением токенов; baseline переснять перед реализацией на фиксированном checkout.
- [Algolia DocSearch](https://docsearch.algolia.com/docs/tips): иерархия заголовков и якоря. [Docusaurus](https://docusaurus.io/docs/search): контекст версии. [QMD](https://github.com/tobi/qmd): ограниченное чтение по ссылке. [Sphinx](https://www.sphinx-doc.org/en/master/usage/referencing.html) и [rustdoc](https://doc.rust-lang.org/rustdoc/lints.html): именованные цели и диагностика ссылок.
- `data/cli-skills-encyclopedia`: Progressive Disclosure, «Токен-эффективность», Agent-Friendly CLI Design. `data/sdd-research/06-качество-и-трассируемость.md`: прямые и обратные связи. Это аргументы дизайна, не нормативные источники продукта.
- Исходная диагностика постановки: `index check` уже падал на битой ссылке `../../../kilo.jsonc` в манифесте. Не чинить чужую правку и не выдавать её за результат этой задачи; для финальной приёмки нужен согласованный снимок без исходного нарушения.
