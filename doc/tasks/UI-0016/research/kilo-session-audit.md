## Рекомендации

1. **Высокий, `go-to-task`.** Требовать один минимальный публичный тест, падающий на исходной реализации, до первой записи кода. Проверка: аудит показывает тест раньше первого `write` реализации.
2. **Высокий, `go-to-task` + workspace.** При незавершённых чужих изменениях в тех же файлах останавливаться или переходить в отдельный worktree до записи. Проверка: snapshot не становится stale из-за чужого файла.
3. **Средний, flow prompt.** После `flow-steps` загружать только текущий `flow-prompt --step`, а не общий контракт. Проверка: нет чтения полного `architecture-contract.md`, если нужен один раздел.
4. **Средний, CLI/тест.** Добавить `task evidence --files-from <list>` и командой проверять несколько AC, чтобы не повторять длинный список `--file`. Проверка: одна команда записывает все CASE без `--replace-snapshot`.
5. **Средний, `kilo-session-audit`.** В digest добавить длительность фаз и токены между пользовательскими сообщениями: сейчас для этого потребовался отдельный SQL.
6. **Низкий, task evidence.** Считать изменение `plan.md` после проверки явным событием и требовать пересъём только затронутых CASE, а не всей серии.
