# Работа с задачами фабрики

Команды ниже запускаются из корня проекта. `arch` в документации означает `python3 doc/tools/arch/__main__.py`. Используйте действующие команды из `--help`. [Дорожная карта](../nextplan.md) описывает будущие возможности.

## Сначала выберите режим

| Запрос | Действие |
|---|---|
| Создать задачу или разложить план на карточки | Прочитать [create-task](skills/create-task/SKILL.md). Результат — проверенные карточки и планы. |
| Выполнить, продолжить или проверить задачу по ключу | Прочитать [go-to-task](skills/go-to-task/SKILL.md). Открыть карточку по точному ключу. |
| Только объяснить, исследовать или провести аудит | Проверить источники и сообщить вывод. Создавать карточку по запросу на её регистрацию. |
| Зафиксировать результаты обсуждения | Прочитать [document-session](skills/document-session/SKILL.md). |
| Меняется каноническая архитектура | Дополнительно прочитать [architecture-docs](skills/architecture-docs/SKILL.md). |

[Каталог скиллов](skills/README.md) — источник условий вызова. Загружайте применимые навыки и документы по ссылкам.

## Какой источник отвечает на вопрос

- **Цель, границы, критерии и зависимости** — `task.json`, уточнения владельца и план текущей стадии. При существенном расхождении остановите затронутый шаг и уточните контракт.
- **Допустимые пути, типы и flow** — [paths.yaml](config/paths.yaml), YAML выбранного типа и потока. Prompt объясняет способ выполнения. Путь из дорожной карты сначала сверяйте с текущей конфигурацией.
- **Текущее поведение** — исходник, тесты и фактический прогон. **Принятое архитектурное решение** — [индекс архитектуры](architecture/README.md), capability, flow или ADR. Для навигации по коду используйте граф, если он доступен, и подтверждайте вывод исходником.
- **Справочные практики** — [MOC в data/](../data/README.md) → оглавление области → нужный раздел. Используйте при конкретном вопросе. Вывод со ссылками храните в задаче. `data/` служит справочником при работе над фабрикой.

## Цикл выполнения

1. **Проверьте вход.** `git status --short`, `arch task validate <key>`, `arch task diagnose <key> --json`. Прочитайте активную стадию, выбранные prompts и записи зависимостей. Текущий CLI не подтверждает всю готовность.
2. **Сопоставьте результат и проверку.** Для каждого AC определите наблюдаемое поведение и команду или способ проверки. Для дефекта воспроизведите симптом, если это возможно. Выделяйте подзадачу для результата, который можно принять отдельно, с учётом политики типа.
3. **Сделайте ограниченный срез.** Сохраните чужие изменения. Если изменения пересекаются с вашей задачей и безопасно отделить их нельзя, уточните дальнейшие действия. При изменении контракта обновите ближайшие тесты и документацию, которую это затрагивает.
4. **Проверьте итог.** Сначала целевые проверки, затем нужные проверки смежных контрактов. Запишите в `stageN/verification.json` фактические команды, исходы, AC и проверенный снимок. Укажите пропуски и причины. Проверьте итоговый diff.
5. **Закройте по результату.** Проверьте каждый обязательный AC, объявленные подзадачи, актуальность результатов и требуемое одобрение. Подтвердив эти условия, используйте `arch task close <key>`. Неполная проверка или ожидание владельца отражаются в статусе задачи.

## Инварианты

- Единственный вход — `task.json`. Используйте `stageN/plan.md` и `stageN/verification.json`, где они нужны. Номер выдаёт владелец или утверждённый реестр. UI использует `UI-NNNN`, Jira — `NNNN`, иной источник — зарегистрированный префикс.
- Исходный intent, scope и критерии во время реализации меняются только явным уточнением. Технические результаты записываются в стадию и в существующие поля состояния. Новые пути проверяйте по `allowed_paths`.
- Для локальной работы используйте известный checkout в пределах scope. `task workspace` выдаёт метаданные и подсказку ветки. Отдельная среда нужна по условиям задачи. Целевую ветку и релиз уточняйте, когда от них зависит нужное действие.
- Push, merge, deploy и запись во внешний трекер выполняются по явному разрешению. CLI выполняет структурные проверки, агент оценивает смысл и сообщает, чего не удалось подтвердить.
