# Агентский инструктаж фабрики (`doc/`)

## Где вы находитесь

Вы в корне агентской software factory: `/home/user/doc/`. Корень песочницы (`/home/user/`) содержит сервисные правила (Манифест, `doc.architecture.md`, аудит, исследование) — они **не** часть завода. `data/` — внешний справочник, не править как проектные файлы.

## Точка входа

1. Читайте `doc/architecture/README.md` — краткая карта архитектуры и протокол чтения.
2. Используйте `doc/tools/arch.py` только для детерминированных операций: `list`, `show <id>`, `index build`, `index check`, `validate`. CLI не принимает смысловых решений.
3. Навыки — в `doc/skills/` (`create-task`, `go-to-task`, `задокументируй`). Используйте только навык, relevant к текущему intent.

## Задача — контракт

- Единственный canonical input: `task.json`. **Нет `task.md`**, нет копий манифеста в `doc/`.
- `task_number`: ровно 4 цифры. Jira — bare number (`1234`), UI — `UI-1234`, иные источники — явный префикс (`GH-1234`). CLI валидирует, но никогда не выделяет номер сам.
- Четырехзначные номера реестрируются в `doc/architecture/system/task-number-registry.md`; дубли — стоп.

## Архитектура

- `doc/architecture/` — Markdown + YAML frontmatter, `index.json` генерируется.
- Существенные изменения фиксируются в `doc/architecture/decisions/` (ADR) и применяются только после ревью/одобрения.
- `stageN/architecture-delta/` — предложение дельты к текущим спецификациям, не текущая истина.

## Правила агента

- Не угадывайте неопределённое — спросите.
- Не дублируйте истины; ссылкуйте на canonical страницы.
- Агентская самодокладка не является доказательством; нужны тесты/evidence + человеческое approval.
- Не пушат/мерджат/деплоят без явного разрешения.
