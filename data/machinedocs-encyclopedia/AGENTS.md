# Инструкции агенту для Obsidian-хранилища

Эта энциклопедия — Obsidian vault и LLM-maintained knowledge base. Сначала прочитай [[Индекс]] и только затем загружай релевантные страницы. [[Главная]] — тематическая карта для человека; индекс — полный каталог для поиска агентом.

## Структура и источник истины

- `Практики/`, `Архитектура/`, `Документация/`, `Форматы/`, `Примеры/` содержат канонические тематические страницы. У одного понятия — одна основная заметка; подробности дополняй там, а не копируй в несколько документов.
- `Глоссарий.md` — краткие определения терминов и ссылки на канонические заметки; не превращай его в параллельную статью.
- `Индекс.md` — полный список Markdown-документов с кратким description и ссылкой; обновляй после создания, удаления, переименования или существенной смены scope.
- `Журнал.md` — append-only журнал значимых ingest/research/lint/обновлений. Не переписывай старые записи; добавляй новую датированную запись.
- Внешняя публикация / спецификация / репозиторий остаётся источником факта. Энциклопедический текст — производное изложение; не объявляй его первоисточником. Сохраняй URL, дату/версию при наличии, тип источника и границы применимости.

## Как документировать исследование

1. Разделяй наблюдение/цитируемый результат, авторскую интерпретацию, гипотезу и практическую рекомендацию.
2. Для численных/временных/current claims указывай источник рядом с утверждением; добавляй дизайн исследования, популяцию и ограничение переноса, если они важны.
3. Vendor-, author- и method-owner claims маркируй как таковые. Case study показывает применение, а не причинность.
4. Если вывод меняет несколько страниц, обнови каноническую заметку, глоссарий при новом устойчивом термине, связанные заметки, `Индекс.md` и `Журнал.md`.
5. Не выдумывай свойства, пути репозитория, названия, DOI, версии или термины. Если факта не хватает — явно оставь неизвестным.

## Obsidian-ссылки и relative paths

- Используй `[[wikilinks]]` для концептуальных ссылок и backlinks. Когда возможно совпадение названий или ссылка из индекса, указывай vault-relative путь: `[[Практики/Название заметки]]`; для alias-display используй `[[Практики/Название заметки|Отображаемый текст]]`.
- Для обычных Markdown-ссылок на локальные файлы используй относительный путь от текущего документа (`../Практики/Название%20заметки.md`), не `/home/user/...`, `file://` или sandbox-specific абсолютные пути.
- Не меняй существующие короткие wikilinks на длинные пути без причины: Obsidian их разрешает по уникальному имени. При создании новых ссылок проверяй цель и регистр/символы.
- Все заметки должны быть достижимы из `Индекс.md` и иметь содержательные связи из `Связи`/контекста. Не создавай искусственные ссылки лишь ради степени узла.
- Для `[[target#heading|label]]` проверяй и заметку, и заголовок, если ссылка зависит от него. После rename/move перепроверь backlinks и ссылки.

## Машиночитаемость и контекстные бюджеты

- Стандарт frontmatter для тематических заметок: `title`, `description`, `paths`, `tags`, `aliases`.
- `description` — короткий триггер загрузки: когда документ нужен. Не пересказывай статью общими словами.
- `paths: []` допустим для энциклопедического материала, не привязанного к конкретному исходному репозиторию. Не придумывай glob-пути. Для repo-specific документа задавай реальные пути и scope.
- Используй один H1, информативные H2/H3, краткий блок «Коротко/Определение», явные условия применимости, ограничения, примеры и `## Связи`.
- Чанки должны быть самодостаточны; расшифровывай редкие сокращения при первом употреблении; таблицы и YAML — только если добавляют понятную структуру.
- Не помещай весь vault в обязательный контекст агента. Сначала индекс/карта, затем страницы, соответствующие задаче; длинные методические заметки загружай по триггеру.
- Не превращай поясняющие инструкции в hard policy. Безопасность/полномочия должны enforce-иться инструментами и CI, а не только прозой.

## Workflow изменений

1. Прочитай `Индекс.md`, `AGENTS.md` и релевантные канонические/исследовательские страницы.
2. Сформулируй scope, проверяемые источники/код и что является новой информацией.
3. Измени минимальный набор канонических заметок; добавь обратные/соседние Obsidian links там, где это помогает навигации.
4. Обнови глоссарий только для устойчивых терминов и индекс для каждой новой страницы.
5. Запусти `python3 scripts/lint_wiki.py` и `python3 scripts/build_index.py --check`.
6. Исправь сломанные ссылки, отсутствующие метаданные и orphan страницы; не подавляй ошибки исключениями без объяснения.
7. Добавь краткую датированную запись в `Журнал.md`; итоговый ответ перечисляет созданные/изменённые файлы и проверки.
