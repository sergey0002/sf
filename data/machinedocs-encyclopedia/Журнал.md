## [2026-11-21] decision input | task.json canonical и границы CLI/agent

- По уточнению пользователя скорректирован единственный корневой [манифест](../../Манифест%20агентной%20software%20factory.md): `task.json` — единственный canonical task input для ядра; отдельный hand-authored `task.md`/`doc.md` не требуется. В JSON должны присутствовать все поля, необходимые детерминированным CLI-операциям и последующему агентскому исполнению; human-readable представления не формируются по умолчанию и, если понадобятся, являются только derived views.
- Зафиксировано разделение: CLI (предпочтительно Python; shell — тонкий wrapper без дублирования логики) выполняет структурные/детерминированные операции, adapters, snapshots, schema validation, безопасные IDs/paths/branches, scaffold, Git/diff и test/evidence capture. Агент через skills/instructions отвечает за intent, уточнения, семантический поиск, impact analysis, план, выбор проверок и содержательные архитектурные выводы. CLI не имитирует semantic understanding/fuzzy inference/маски.
- Обновлено исследование формата project docs/task intake, чтобы прежнее сравнение `task.json + task.md` не выглядело текущей рекомендацией; альтернативы сохранены как анализ, итог следует новой явной вводной. Текущая проектная стадия остаётся single-agent core; не принято решений о полной JSON Schema, exact CLI command list или vendor.
- В манифесте отдельно закреплён текущий scope одного агента; dependency graph/subagent orchestration оставлены будущими опциями. Корневой манифест остаётся единственной копией по пути `/home/user/Манифест агентной software factory.md`; в энциклопедию он не копировался. После правок wiki lint прошёл: 58 Markdown-файлов, 739 resolved internal links; `build_index.py --check` подтвердил актуальный индекс.

## [2026-11-21] architecture input | role-based model CLI fallback

- В единственный корневой манифест добавлена capability: отдельный model CLI client обращается к нескольким моделям через OpenAI-compatible API; versioned config задаёт providers/models и явный `role → model` mapping. Пример и command contract помечены как sketch, без выбора endpoint, model ID или библиотеки.
- Зафиксировано различие: CLI маршрутизирует explicit call, проверяет формальную output schema и сохраняет call evidence; agent skill выбирает роль, контекст и инструкцию, интерпретирует вывод. Это stateless model consultation/fallback для слабой поддержки native subagents, не полный subagent runtime, execution sandbox или task orchestrator.
- В оценке записаны trade-offs: portability/fallback и явная конфигурация против дополнительных data/credential egress, cost/latency и несовпадения provider-specific API capabilities. Рекомендован лёгкий Python client, shell wrapper; custom proxy отложен до обоснованной нужды в central policy/credentials/audit/rate limits. Добавлены ограничения по secrets, allowlist, timeout/cost, output validation и eval tests.
- Обновлена research note о task formats, чтобы отразить model CLI как отдельную capability, не как часть `task.json` и не как внедрённый multi-agent workflow. Основной scope — один агент.
- Проверки после обновления: 58 Markdown-файлов, 741 resolved internal links; `python3 scripts/lint_wiki.py`, `python3 scripts/build_index.py --check` и sanity-check манифеста прошли.

## [2026-11-21] design input | Не перегружать CLI документированием

- По уточнению пользователя зафиксировано: не делать CLI обязательным посредником для всех Markdown-правок и не проектировать CRUD для каждого типа документации заранее. Для небольших prose edits допустима прямая правка агентом/человеком; типизированные операции glossary/flow рассматривать только при конкретной выгоде — schema/ID/link validation, атомарный patch, revision/conflict safety или точечная запись.
- Агент сохраняет ответственность за семантический выбор сущности и подготовку содержимого; CLI — за явное применение и детерминированные проверки. Вызов CLI сам по себе не экономит токены; стоимость сравнивать по контексту, output patch, числу итераций и ошибкам.
- Открытый вопрос: на tabletop walkthrough сопоставить необходимость и ожидаемую выгоду прямого Markdown edit и типизированного docs CLI. Фактические измерения токенов/latency/ошибок — только в будущем одобренном пилоте с соблюдением всех prerequisites; пилот сейчас не запускается и write API не утверждён.
- Обновлены единственный корневой манифест и research note; копию манифеста в encyclopedia не создавали.
