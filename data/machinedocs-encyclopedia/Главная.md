# 🏠 Энциклопедия машиночитаемой документации для агентской работы

Самодостаточное хранилище (Obsidian vault) о лучших практиках оформления
документации, машиночитаемой для AI-агентов на больших программных проектах.
Навигация — через `[[wikilink]]`, теги `#формат`, `#архитектура`, `#практика`.

> [!tip] Для человека и агента
> [[Индекс]] — полный каталог заметок с краткими триггерами и относительными ссылками; [[AGENTS.md]] — правила поддержки vault; [[Журнал]] — датированная история изменений.

> [!tip] Как читать
> Для навигации используйте [[Индекс]] (полный каталог) или [[Главная]] (curated карта); для методов поддержки vault — [[LLM Wiki и поддержка Obsidian]] и [[AGENTS.md]].
> Тематические заметки используют общий машиночитаемый каркас; диаграммы, примеры и дополнительные блоки добавляются там, где они реально помогают.

## Ключевые факты (2026)

- **llms.txt** (Jeremy Howard, сентябрь 2024): курируемый Markdown-индекс в корне сайта;
  принят Anthropic, Stripe, Vercel, Cloudflare; читают Cursor, Continue, Cline.
- **Codified Context** (arXiv, проект 108K строк C#): hot memory (конституция) +
  19 доменных агентов + cold memory (34 спецификации) — документация как инфраструктура.
- **AGENTS.md**: >60,000 open-source проектов (Linux Foundation); v1.1 добавляет
  frontmatter и индексный формат.
- **OKF** (Open Knowledge Format, Google Cloud): Markdown + YAML frontmatter,
  обязательный type, index.md/log.md.
- **AI-native docs**: structured-first, explicit metadata, semantic chunking;
  качество retrieval зависит от задачи, корпуса и eval-набора — измерять локально.
- **Lost in the Middle**: факты в середине контекста теряются — index-first подход.
- **Fitness functions**: объективные архитектурные правила — в детерминированные CI-гейты
  (ArchUnit, dependency-cruiser); enforcement проверяется на каждом CI-запуске.
- **Анти-велосипеды**: queryable каталог компонентов + reuse decision rule
  (USE_EXISTING | EXTEND | KEEP_LOCAL); правила тремя путями.
- **Executable specs**: acceptance criteria observable/atomic/bounded; spec commit before run;
  тесты пишет одна сессия, код — другая.
- **Большие базы**: иерархические context-файлы с lazy loading; agentic search вместо RAG;
  REPOSITORY_MAP.md + per-module CONTEXT.md; LSP для символов.
- **Аудит кода**: гейты перед человеком (secrets, SAST, SCA); качество/риск AI-кода
  зависит от задачи и метода измерения; глубина ревью по риску; provenance и CI evidence.
- **Agentic SDLC**: Intent→Plan→Build→Verify→Secure→Deploy→Observe→Improve;
  4 фазы внедрения (assisted → adaptive); стек: orchestration, sandbox, policy engine.
- **Уровни автономии 0–5**: от Suggest до Autonomous Merge; уровень — по риску задачи.
- **CA/CD**: self-healing pipelines и tiered autonomy; результаты auto-resolution зависят
  от класса сбоев и должны валидироваться локальными evals; governance с начала.
- **Harness**: runtime + tools + sandbox + permissions + evals/telemetry; каждое изменение
  harness/prompt/model проверяется на фиксированных задачах.
- **Задача агенту**: issue-first контракт — scope, negative constraints, критерии,
  полномочия и доказательства; handoff хранится в issue/PR, не только в чате.
- **MCP security**: tool descriptions и результаты — недоверенная поверхность;
  authorization проверяется на исполнении; для чувствительных действий — явный approval.
- **Измерение**: task outcome + policy safety + reliability + cost + review burden;
  не оптимизировать PR count, tokens, coverage или green CI отдельно от rework/incidents.
- **Параллельные агенты**: worktree изолирует файлы/index, но не shared services и не семантические
  конфликты; сначала ownership/contracts, затем последовательная интеграция и полный CI.
- **Threat model**: issue/PR/комментарии — attacker-controlled input; защищать policy source,
  credentials, runners, tools и release path как единую цепочку.
- **Операционная модель**: пилот → bounded PR automation → policy-based workflow;
  масштабировать после baseline, evals, review capacity и rollback readiness.
- **Критический баланс**: код — source of truth для текущего наблюдаемого поведения;
  intent/rationale/policy часто не выводятся. Контекст и ограничения добавлять только
  когда они улучшают локальные evals или enforce важные инварианты.
- **Software factory**: сначала module/dependency/contracts/ownership/runtime map;
  параллелить read-only аудит, сериализовать overlapping mutations; fixes ограничены scope,
  проверяются независимым verifier и детерминированными gates. Увеличивать автономию поэтапно.
- **Context engineering**: write/select/compress/isolate; отделять project policy, task state и memory,
  передавать агентам typed handoffs с provenance, проверять изменения контекста офлайн и через безопасный rollout.

## Принципы этого хранилища

1. Одна canonical тема/формат/практика — одна страница; добавляй новую только если не плодится дублирование.
2. У заметки один H1, короткое summary/description, полезная структура и ссылки; пример/таблица/диаграмма — только когда добавляют ценность.
3. Навигация в два слоя: [[Главная]] — curated MOC, [[Индекс]] — полный список с trigger summaries; агент сначала индексирует, затем точечно читает релевантные файлы.
4. Семантические связи — Obsidian `[[wikilink]]` / backlinks; список файлов в индексе использует относительные Markdown paths; обе формы проверяются.
5. Источники и выводы трассируются: claims, interpretation, recommendation и uncertainty не смешиваются; термины ведут в [[Глоссарий]] и canonical notes.
6. Теги: `#формат`, `#архитектура`, `#практика`, `#машиночитаемость`; metadata schema — [[Frontmatter-схемы]].
7. Diagrams — Mermaid, по необходимости; не добавлять шаблонные секции/мнемоники ради одинакового объёма.
