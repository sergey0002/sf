# 📚 Глоссарий терминов машиночитаемой документации

> Полный каталог форматов — [[Справочник форматов]].

## A–D

- **AGENTS.md Index** — AGENTS.md как lazy-load индекс документов. См. [[AGENTS.md Index]].
- **Agent Runtime** — среда исполнения agent loop и tool calls. См. [[Инструменты агентной среды]].
- **Agent Evals** — повторяемая оценка task outcome, trajectory, policy и затрат. См. [[Evals и метрики агентной разработки]].
- **Agentic Operating Model** — роли, policy, платформы и cadence для безопасного масштаба. См. [[Операционная модель агентных команд]].
- **Agent Threat Model** — угрозы коду и действиям агента по всему SDLC. См. [[Threat model агентной разработки]].
- **Agentic SDLC** — Intent→Plan→Build→Verify→Secure→Deploy→Observe→Improve. См. [[Сквозной цикл разработки]].
- **AHE** — экспериментальный evaluate→analyze→improve цикл для харнеса. См. [[Harness-инжиниринг]].
- **Autonomy Levels 0–5** — Suggest → Draft → Propose → Bounded → PR → Autonomous. См. [[Уровни автономии]].
- **CA/CD** — Continuous Agentic/Continuous Deployment; агентная автоматизация доставки. См. [[Агентский CI-CD]].
- **Ephemeral Runner** — одноразовый CI runner, удаляемый после job. См. [[Инструменты агентной среды]].
- **AI-Native Documentation** — документация, написанная для агентов. См. [[AI-Native Documentation]].
- **AI-Readiness Score** — оценка машиночитаемости документации (0–100). См. [[AI-Readiness scoring]].
- **Atomic Units** — атомарные единицы информации без зависимости от контекста. См. [[Структурированный Markdown]].
- **Code as Documentation** — код как источник фактов о текущем исполняемом поведении, не о полном intent. См. [[Код, контекст и минимальный harness]].
- **Codified Context** — инфраструктура контекста: hot memory + агенты + cold memory. См. [[Codified Context (3 яруса)]].
- **Cold Memory** — спецификации, загружаемые по требованию. См. [[Codified Context (3 яруса)]].
- **Constitution** — горячая память: всегда-загружаемая конституция проекта. См. [[Codified Context (3 яруса)]].
- **Docs-as-Code** — документация как код: версионирование, CI, ревью. См. [[Docs-as-Code и CI]].
- **ТРИЗ (TRIZ)** — теория решения изобретательских задач; в разработке ПО полезна как эвристика формулирования противоречий и генерации альтернатив, не как автоматический oracle. См. [[ТРиЗ и системные методологии для разработки ПО]].
- **Техническое противоречие** — улучшение характеристики A ухудшает B; до выбора решения нужно подтвердить механизм и метрики конфликта. См. [[ТРиЗ и системные методологии для разработки ПО]].
- **IFR (Ideal Final Result)** — целевое состояние, где полезный эффект достигается без неприемлемого вреда/новых ограничений; в software task задавать проверяемо. См. [[ТРиЗ и системные методологии для разработки ПО]].
- **QAW (Quality Attribute Workshop)** — выявление и приоритизация quality-attribute scenarios для software architecture. См. [[Альтернативы ТРИЗ для агентной разработки ПО]].
- **ADD (Attribute-Driven Design)** — итеративное проектирование архитектуры на основе quality scenarios, функций и constraints. См. [[Альтернативы ТРИЗ для агентной разработки ПО]].
- **ATAM** — метод анализа архитектурных рисков, sensitivity points и tradeoffs. См. [[Альтернативы ТРИЗ для агентной разработки ПО]].
- **DMAIC** — Define, Measure, Analyze, Improve, Control; цикл улучшения измеримого существующего процесса. См. [[Альтернативы ТРИЗ для агентной разработки ПО]].
- **GMA (General Morphological Analysis)** — структурирование качественного многомерного design space и оценка совместимости конфигураций. См. [[Альтернативы ТРИЗ для агентной разработки ПО]].
- **Quality-attribute scenario** — проверяемый сценарий стимула, среды, затронутого артефакта, реакции и меры качества; основа QAW/ADD/ATAM.
- **ARIZ-85C** — итеративный алгоритм ТРИЗ для моделирования, переформулирования и решения сложной изобретательской задачи; не равен матрице противоречий. См. [[ТРИЗ и аналоги: карта методов для агентной разработки]].
- **Contradiction Matrix** — таблица подсказок 40 принципов для пар инженерных параметров; программные атрибуты нельзя механически считать её параметрами. См. [[Ресёрч по теориям ТРИЗ и аналогам для агентных систем]].
- **Physical contradiction / separation** — требование противоположных состояний элемента с поиском разделения по времени, месту, условию или структуре. См. [[ТРИЗ и аналоги: карта методов для агентной разработки]].
- **Su-Field (Substance–Field) analysis** — модель взаимодействия двух substances через field для постановки задачи и применения 76 стандартов; в цифровых системах требует предметной адаптации.
- **Nine Windows / System Operator** — рамка анализа subsystem/system/supersystem через прошлое/настоящее/будущее; средство структурирования, не causal model/forecast.
- **GMA / Cross-Consistency Assessment** — многомерное качественное пространство альтернатив с попарной проверкой совместимости; не вероятностная или причинная оценка. См. [[ТРИЗ и аналоги: карта методов для агентной разработки]].
- **SIT (Systematic Inventive Thinking)** — компактный TRIZ-derived набор эвристик генерации идей; не независимое подтверждение эффективности ТРИЗ. См. [[Ресёрч по теориям ТРИЗ и аналогам для агентных систем]].
- **Su-Field (Substance–Field)** — структурная модель взаимодействия компонентов/субстанций и поля в классической ТРИЗ; цифровая модель требует явного описания actor, object, channel, effect и trust boundary. См. [[ТРИЗ и аналоги: карта методов для агентной разработки]].
- **76 Standard Solutions** — библиотека типовых преобразований Su-Field моделей; не 76 software design patterns. См. [[Ресёрч по теориям ТРИЗ и аналогам для агентных систем]].
- **A3** — evidence-linked problem-solving narrative для current state, gap, causes, countermeasure и follow-up. См. [[Альтернативы ТРИЗ для агентной разработки ПО]].
- **PDCA** — Plan–Do–Check/Study–Act; итеративная проверка изменения на фактах. См. [[Альтернативы ТРИЗ для агентной разработки ПО]].
- **QFD / House of Quality** — перевод customer needs в инженерные характеристики и приоритеты; веса требуют проверки с реальными stakeholders. См. [[Альтернативы ТРИЗ для агентной разработки ПО]].
- **FMEA / FMECA** — анализ failure modes, effects, causes and controls; перечень ограничен опытом и score не является истиной. См. [[Ресёрч по теориям ТРИЗ и аналогам для агентных систем]].
- **TOC (Theory of Constraints)** — поиск и улучшение актуального системного ограничения по данным о потоке. См. [[Альтернативы ТРИЗ для агентной разработки ПО]].
- **Double Diamond** — рамка Discover–Define–Develop–Deliver для исследования problem space и тестирования решений; не RCA/architecture proof. См. [[Альтернативы ТРИЗ для агентной разработки ПО]].
- **CCA (Cross-Consistency Assessment)** — попарная оценка совместимости параметров в GMA; не причинная и не вероятностная оценка. См. [[ТРИЗ и аналоги: карта методов для агентной разработки]].
- **MOC (Map of Content)** — кураторская карта основных тематических входов; в этом vault — [[Главная]], в отличие от полного каталога [[Индекс]].
- **LLM Wiki** — паттерн накопления и связывания знаний в markdown notes, поддерживаемых LLM по фиксированной schema; см. [[LLM Wiki и поддержка Obsidian]].
- **Backlink** — входящая внутренняя ссылка; Obsidian использует их для навигации и графа, но backlink сам по себе не гарантирует смысловой связи.
- **Internal task graph** — durable decomposition of agent work with parent external task ID, dependencies, owner/lease, state, budgets and artifact links. См. [корневой манифест](../../Манифест агентной software factory.md).
- **Agent handoff** — структурированное сохранение состояния/решений/незакрытых вопросов, доказательств и next action между исполнителями; не пересказ чата. См. [[Контракт задачи для агента]], [[Параллельная работа агентов]].
- **Project knowledge model** — связанные сущности, флоу, бизнес-правила, контракты и решения с provenance, owner, version/validity и tests. См. [корневой манифест](../../Манифест агентной software factory.md).
- **Release record / snapshot** — запись о версии/commit, включённых изменениях, затронутой документации, проверках и rollback; должен ссылаться на конкретный релиз, не дублировать current canonical docs. См. [корневой манифест](../../Манифест агентной software factory.md).

## E–M

- **Explicit Metadata** — явные метаданные вместо вывода из структуры. См. [[Frontmatter-схемы]].
- **Frontmatter** — YAML-шапка документа (title, description, paths, tags). См. [[Frontmatter-схемы]].
- **Harnessability** — насколько система допускает автоматические guides/sensors и reliable feedback. См. [[Код, контекст и минимальный harness]].
- **Harness / Harness Engineering** — среда и feedback controls вокруг модели; не обязательно большой набор инструкций. См. [[Harness-инжиниринг]], [[Код, контекст и минимальный harness]].
- **Hot Memory** — всегда-загружаемый слой правил и конвенций. См. [[Codified Context (3 яруса)]].
- **Index-First** — сначала индекс, потом точечная загрузка. См. [[Index-First подход]].
- **llms.txt** — курируемый Markdown-индекс для LLM. См. [[llms.txt]].
- **llms-full.txt** — полная текстовая версия документации для агентов. См. [[llms.txt]].
- **Lost in the Middle** — потеря фактов в середине контекста. См. [[Index-First подход]].
- **Mermaid** — текстовые диаграммы в Markdown. См. [[Mermaid-диаграммы]].
- **NO ASSUMPTIONS** — политика: не выдумывать атрибуты, связи, термины. См. [[Сущности]].
- **Reuse Decision** — USE_EXISTING | EXTEND | KEEP_LOCAL | PROPOSE_SHARED. См. [[Следование архитектуре]].
- **Risk Map** — карта рисков на входе: «know what to prove before». См. [[Следование архитектуре]].
- **Threat Model** — модель угроз агентного кода. См. [[Безопасность]].
- **Ubiquitous Language** — единый язык домена + техническое отображение. См. [[Сущности]].
- **OKF** — Open Knowledge Format (Google Cloud). См. [[OKF (Open Knowledge Format)]].

## N–Z

- **OIDC for CI** — short-lived credentials для pipeline без постоянных cloud keys. См. [[Безопасный деплой агентами]].
- **Policy-as-Code** — машинно-проверяемые правила доступа и promotion. См. [[Безопасный деплой агентами]].
- **Parallel Worktree** — отдельный checkout/index для ветки; общая Git-база и внешние ресурсы остаются. См. [[Параллельная работа агентов]].
- **Progressive Delivery** — постепенное увеличение трафика с analysis и rollback. См. [[Безопасный деплой агентами]].
- **Least Agency** — не давать агенту автономность, не нужную для задачи. См. [[Threat model агентной разработки]].
- **Rework Rate** — доля работы, переделанной после принятия; читать вместе с качеством. См. [[Evals и метрики агентной разработки]].
- **Trajectory Eval** — оценка последовательности tool calls и соблюдения policy. См. [[Evals и метрики агентной разработки]].
- **SLSA Provenance** — attestation о том, где и как собран артефакт; требует проверки. См. [[Безопасный деплой агентами]].
- **Semantic Chunking** — нарезка документации на семантические чанки. См. [[Семантический чанкинг]].
- **Tiered Autonomy** — полномочия агента соразмерны риску/обратимости. См. [[Агентский CI-CD]].
- **Staleness** — устаревание документации; maxAgeDays. См. [[Актуальность и staleness]].
- **Trigger Description** — description как условие загрузки, а не пересказ. См. [[Frontmatter-схемы]].
