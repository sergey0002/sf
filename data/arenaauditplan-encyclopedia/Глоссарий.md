# Глоссарий терминов, дезамбигуация инструментов и кросс-таблица SDD

> [!abstract] Кратко
> Единый словарь канонических понятий хранилища `arenaauditplan`, таблица различения одноимённых внешних инструментов и матрица соответствия артефактов `sf` внешним SDD-фреймворкам. Подробные механизмы раскрыты по ссылкам в канонических заметках.

## 1. Ключевые архитектурные понятия `sf v3.0`

- **Трек А (`Environment-Native Zero-CLI-Change Track`)** — контур немедленного внедрения в агентной среде (`OpenCode`, `Kilo Code`, `Claude Code`) через подключаемые граф-инструменты, progressive-disclosure скиллы и ролевых субагентов без единого изменения кода `arch` CLI. См. [[03-Архитектура-и-контракты/Двухтрековая-архитектура-sf-v3-и-граница-ядра]] и [[05-Этапы-внедрения/F00-Среда-и-субагенты-без-правки-CLI]].
- **Трек Б (`Thin Deterministic Core Track`)** — контур хирургической доработки инвариантного ядра `arch` CLI (кроссплатформенный файловый лок для Windows, автоподключение `state.json + events.jsonl + intent_digest`, блокировка `close` без `approvals`, валидация JSON Schema `verification.json` и `*.flow.json`, `Validity L1`). См. [[05-Этапы-внедрения/F0-Разблокировка-ядра-CLI-и-Windows]].
- **`Envelope` (`Graph-First Envelope`, `≤2 000` токенов)** — строго структурированный JSON-пакет (`files`, `symbols`, `call_paths`, `tests_affected`, `open_questions`), который субагент `locator` собирает через граф кода и передаёт `implementer`-у вместо чтения сырых файлов. См. [[02-Исследования-и-инструменты/Субагенты-и-оркестрация-в-средах-OpenCode-Kilo-Claude]].
- **`Capsule` (`Context Compiler Pack`, `≤3 200–6 000` токенов)** — одношаговый скомпилированный контекстный пакет для слабой модели (`контракт 1 ветки + unchanged_behavior + гибридный срез функции + сжатый через RTK лог оракула`, `0` схем поисковых MCP). См. [[03-Архитектура-и-контракты/Двухтрековая-архитектура-sf-v3-и-граница-ядра]].
- **`Ceremony Scaling` (`quick / standard / full`)** — выбор глубины артефактов задачи по матрице `risk × complexity`: микро-багфикс идёт по рельсу `quick` (`task.json ≤1 КБ`, `1 AC`, `unchanged_behavior`, `1` падающий тест) без многостраничных планов.
- **`unchanged_behavior`** — обязательное поле контракта багфикса (паттерн AWS Kiro), явно фиксирующее инварианты поведения, которые патч **не имеет права** изменить.
- **`Task Flows` vs `Architectural Flows`** — жёсткая доменная граница: *Task Flows* (`doc/config/task-conf/`) управляют шагами работы агента над задачей; *Architectural Flows* (`doc/architecture/**/FLOW-*`, целевой формат `*.flow.json`) моделируют бизнес- и системные процессы самого продукта, таблицы решений DMN и жизненные циклы состояний. См. [[03-Архитектура-и-контракты/Спецификация-архитектурных-флоу-flow-json]].
- **`Oracle-First` (`Red-before-Green`)** — правило, при котором каждый `AC` до правки продуктового кода превращается в сценарий `GIVEN/WHEN/THEN` и тест-оракул, обязанный упасть (`Red`) на текущем `HEAD`. См. [[03-Архитектура-и-контракты/Конвейер-верификации-оракулы-и-песочница]].
- **`RO Trust Zone`** — физический запрет на редактирование `tests/**`, `*.flow.json` и конфигов гейтов для роли/фазы `implementer` (через права субагента и/или read-only mount `bwrap`/контейнера).
- **`Independent Per-Function Verifier`** — изолированный ревьюер на другой модели (без доступа к рассуждениям автора патча), проверяющий каждую изменённую функцию по одной на 4 вопроса протокола Winninger (`54.5% → 90.9%` полноты обнаружения скрытых дефектов на малой модели).
- **`Validity L1` (`Suspect Links`)** — детерминированный контроль актуальности входов незакрытых задач (`snapshot` SHA-256 документов/схем/символов, где `unknown ≠ current`), блокирующий старт по устаревшему контракту. См. [[01-Аудит-текущей-системы/Моделирование-сценариев-и-режимы-отказа-F1-F14]].
- **`Cold Resume`** — протокол восстановления прерванной автономной сессии через `events.jsonl` replay, JSON-флаги кейсов `"passes": false` и принудительный входной smoke-прогон уже закрытых подзадач перед переходом к следующей.
- **`5-Boundary Sandbox`** — изоляция автономных прогонов по 5 независимым периметрам: `compute`, `filesystem allowlist`, `network egress allowlist`, `identity`, `data/secrets` (так как голый `git worktree` не является песочницей безопасности).

## 2. Критическая дезамбигуация одноимённых внешних инструментов

> [!warning] Не смешивать однофамильцев!
> В экосистеме 2025–2026 гг. существуют **четыре разных продукта с именем `CodePrizm / CodePrism`** и **три разных проекта с именем `CodeGraph`**. Подробные характеристики сведены в [[02-Исследования-и-инструменты/Подключаемые-графы-кода-аудит-и-компрессоры]].

| Точное имя и автор | Лицензия и класс | Для чего используется в `sf v3.0` |
|---|---|---|
| **`Green Olive Tech CodePrizm`** (`greenolivetech.com/products/codeprizm`) | Коммерческий **batch-сервис валидированного аудита** (Request Access, `<30 мин`, `85.5%` точности) | Периодический независимый аудит репо (раз в спринт / перед релизом) с line-level ссылками → регистрация `audit`-задач и `architecture-delta` |
| **`knight22-21/CodePrism`** (`codeprism-ai`, Python) | OSS Python-библиотека и CLI (`Tree-sitter + SQLite`) | Локальный `200–800`-токенный слайсер символа, `Session Overlay` и предзаписной фильтр `SecurityGate` |
| **`rustic-ai/codeprism`** (Rust) | Экспериментальный Rust MCP-сервер (`trace_data_flow`, `analyze_api_surface`) | Опциональный анализ потоков данных и публичной поверхности API |
| **`mirrorsecurity CodePrism`** | Сторонний однофамилец по ИБ | В стеке `sf` **не используется** |
| **`colbymchenry/codegraph`** (57k★) | **MIT**, live-граф с **одним главным тулом `codegraph_explore`** + `codegraph affected` + 17 фреймворков вкл. Laravel | **Базовый навигатор для слабых моделей** (минимум ошибок выбора тула) и авто-поиск затронутых тестов |
| **`codegraph-ai/CodeGraph`** | Rust бинарник (одновременно LSP для IDE + MCP `--profile=core` на 8 тулов, 38 языков) | Опциональный единый сервер для IDE разработчика и узкого MCP-профиля архитектора |
| **`websines/codegraph-mcp`** | Rust + SQLite + кросс-языковой матчинг фронт/бэк REST/GraphQL | Опциональный резолвер межъязыковых HTTP/GraphQL вызовов |

## 3. Соответствие понятий `sf` и внешних SDD/агентных фреймворков

| Понятие в `sf v0.2` | GitHub Spec Kit | Fission OpenSpec | AWS Kiro | Anthropic / Ralph | Канон в `sf v3.0` (`Трек А + Трек Б`) |
|---|---|---|---|---|---|
| `ARCH-contract` + `AGENTS.md` | `constitution.md` | `openspec/specs/` (truth) | `steering/*.md` | `CLAUDE.md` | Модульный `ARCH-contract ≤5 КБ` + `AGENTS.md ≤60 строк` + `*.flow.json` + граф `Graphify` |
| `task.json` (`intent`) | `spec.md` (`specify`) | `changes/<id>/proposal.md` | `requirements.md` (EARS) | `feature_list.json` | Компактный `task.json` (`intent_digest` + `unchanged_behavior` + `passes: false`) |
| `stage1/plan.md` | `plan.md` + `tasks.md` | `design.md` + `tasks.md` | `design.md` + `tasks.md` | `progress.txt` | `envelope ≤2k` + машинный `workpack.json` + `flow-delta.json` (с авто-рендером `plan.md`) |
| `subtasks/NNNN` | `tasks.md` (`[P]`) | чек-лист задач | `waves` | итерации цикла | Изолированные подзадачи в волнах `waves` / `Kilo Agent Manager` со своими ветками и `worktree` |
| `verification.json` + `evidence` | `checklist` + `analyze` | `verify` | `spec validation` | `passes: true` + e2e | Строгая JSON Schema `verification.json` + `RO Trust Zone` + `Winninger Verifier` + `Diff-Mutation` |
| Слияние знаний в канон | `converge` | `openspec archive` (`ADDED/MODIFIED/REMOVED`) | обновление спек | `git commit` | `flow delta apply` + детерминированные `arch analyze` / `arch converge` |
