# Аудит форматов, JSON-схем, хранения и валидации `doc/architecture`

> [!abstract] Кратко
> Сквозная проверка всех `46` файлов `doc/architecture/` (`45` в `index.json` + `README.md`), схем `document.schema.json`, `index.schema.json` и `15` файлов `schemas/bodies/*.json` выявила опасный «театр валидации»: функция `validate_document_body()` в [body_validation.py](<../../../doc/tools/arch/body_validation.py>) из-за тройного бага **всегда возвращает `[]`**, пропуская **`15 из 45` документов (`33.3%`)**, нарушающих собственные body-схемы; между `ARCH-contract` §6.2 и `document.schema.json` накопилось **6 прямых противоречий**; в репозитории живут **два расходящихся на `23 041 Б` манифеста**, а папка `stage{stage}/architecture-delta/` заблокирована правилами `paths.yaml`.

## 2. Шесть структурных противоречий между `ARCH-contract` §6.2 и `document.schema.json` (`PROB-35`)

| Аспект контракта | Принятый `ARCH-contract` §6.2 | `paths.yaml` / скиллы | Исполняемая [document.schema.json](<../../../doc/architecture/schemas/document.schema.json>) | Следствие |
|---|---|---|---|---|
| `additionalProperties` | **`false`** («не скрывать опечатки») | Закрытый список полей в скилле | **`true`** | Опечатки (`implemnted`, `relatd`, `owners`) молча проходят `arch validate` и теряются в `index.json` |
| Формат `source_refs` | Массив **объектов** `{kind, repo, path, symbol, pointer, revision, url}` | Не проверяется | Массив **строк** (`{"type": "string"}`) | Документ, оформленный строго по принятому контракту §6.1, отвергается `arch validate`! |
| Паттерн `id` | `^[A-Za-z][A-Za-z0-9._:-]*$` (`3..96`) | `^[A-Za-z][A-Za-z0-9._:-]*$` | `^[A-Z][A-Za-z0-9_-]*$` | Три разных правила: схема запрещает `.` и `:` и не проверяет длину |
| Перечисление `type` | Явный `enum` из 26 типов | `project.document_types` (26 типов) | Свободный паттерн `^[a-z][a-z0-9-]*$` | `arch validate` пропускает несуществующие типы (`note`, `view`), если не вызван `docs paths --check` |
| Условные поля жизненного цикла | `allOf`: `decision → decision_status`; `superseded → superseded_by` | Обязательно по `architecture-docs` | **Отсутствуют** в схеме | ADR без `decision_status` и устаревший док без `superseded_by` проходят без ошибок |
| Поля `implemented`, `aliases`, `owner` | Описаны в §6.2 и используются в поиске/индексе | Описаны в скиллах | **Отсутствуют** в `document.schema.json` | Типы `implemented` и `aliases` не валидируются при проверке документа |

## 3. Тройной баг `body_validation.py` (`PROB-34`) и полный список 15 невалидных документов корпуса

Функция `validate_document_body()` в [body_validation.py](<../../../doc/tools/arch/body_validation.py>) является полным **no-op**:
1. Читает ключи из корня словаря JSON Schema (`schema.get("required_sections", [])`) вместо `schema["properties"]`, всегда получая `[]` / `None`.
2. Извлекает заголовки без префикса `## ` (`"Последствия"`), а сравнивает со строками с префиксом (`"## Последствия"`).
3. Не очищает fenced code blocks и суффиксы `{#section-id}` (`## Требования {#anchors}` не совпадает с `"## Требования"`). Плюс шаблоны в `ARCH-contract` §5.5 написаны с английскими H2 (`## Purpose and scope`), а `schemas/bodies/*.json` требуют русские H2!

## 4. Нарушения модели хранения, отказы `arch docs read` и локальные пути (`PROB-25, 36–38`)

1. **Два расходящихся манифеста (`PROB-36`):** корневой [Манифест агентной software factory.md](<../../../Манифест агентной software factory.md>) (`113 944 Б`) и [doc/architecture/system/manifest.md](<../../../doc/architecture/system/manifest.md>) (`MAN-software-factory`, `136 985 Б`) разошлись на **`23 041 Б`** (в корневом есть принципы `15`/`15a` о клиентонезависимости среды, в `system/manifest.md` их нет, но есть принцип `17` и `33` непроверяемых ссылки Obsidian `[[wikilink]]` вопреки запрету `ARCH-contract` §3.6!). Одновременно `SYS-simple-factory` и `MAN-software-factory` оба имеют `type: system` вопреки правилу «один на систему», а корневой файл `Исследование software factory — пробелы и готовые практики.md` (`25.3 КБ`) дублирует одноимённую статью в `data/machinedocs-encyclopedia/Практики/` (`32.4 КБ`).
2. **Блокировка `architecture-delta` в `paths.yaml` (`PROB-37`):** каталог `doc/tasks/<task_key>/stage<N>/architecture-delta/` специфицирован в `ARCH-contract` §5.5J, но не внесён в `paths.yaml` (`only_declared_paths: true`), поэтому создание дельты роняет `arch docs paths --check`.
3. **Падение `arch docs read` по `SECTION-TOO-LARGE` и устаревание `SPEC-cli-implementation` (`PROB-38`):** секция `SPEC-cli-implementation#9-cli-clipy` (`35 097 Б`) и секция хранения в `MAN-software-factory` (`56 230 Б`) превышают дефолтный лимит `32 768 Б` и завершаются с `exit 1`; при этом `SPEC-cli-implementation` ссылается на удалённый монолит `cli.py` и не описывает 8 реальных модулей (`doc_ops.py`, `flows.py`, `plan_policy.py`, `project_config.py`, `sections.py`, `session_audit.py`, `task_record.py`, `cli/commands/session.py`).
4. **8 абсолютных путей рабочей станции (`PROB-25`):** локализованы в `architecture-contract.md` (`1`), `manifest.md` (`3`), `runbook.md` (`1`), `architecture-audit.md` (`1`), `ADR-0001-docs-structure-and-boundaries.md` (`2`).
