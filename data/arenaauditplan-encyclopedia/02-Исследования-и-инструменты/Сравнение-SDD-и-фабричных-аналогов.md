# Сравнение с 16 классами SDD-инструментов и агентных фабрик (матрица 18 критериев)

> [!abstract] Кратко
> По таксономии Birgitta Böckeler ([MartinFowler.com](https://www.martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html)), целевая ниша `sf` — строго **`spec-anchored`** (живые контракты и дельты рядом с кодом), а не одноразовый `spec-first` и не хрупкий `spec-as-source` (регенерация всего кода по типу Tessl). По 18-критериальной инженерной шкале текущая `sf v0.2` набирает **`14/54` баллов**, лучшие рыночные аналоги (`OpenSpec`, `Kiro`, `Tessl`, `mini-swe/Agentless`) — **`26–28/54`**, а объединённая архитектура `sf v3.0` (`Трек А + Трек Б`) закрывает **`54/54`**.

## 1. Сравнительная матрица 16 классов решений (2025–2026)

| Система / Подход | Класс решения | Средний расход токенов на задачу | Масштаб `100K–10M LOC` (полиглот) | Надёжность на **слабых моделях (`7B–32B`)** | Защита от багов и «фальшивых тестов» | Главная сила (что берём) и главный изъян |
|---|---|---|---|---|---|---|
| **1. GitHub Spec Kit** ([spec-kit](https://github.com/github/spec-kit), [ref](https://github.github.com/spec-kit/reference/agentic-sdd.html)) | SDD Toolkit (`spec-first`: `specify→clarify→plan→checklist→tasks→analyze→converge`) | `121K–181K` («кувалда по ореху») | Слабо: папки фич без карты системы | **Низкая:** тонет в 8 многословных `.md` | Низкая: `analyze`/`converge` выполняет сама LLM | **Берём:** фазы `clarify / analyze / converge`, делая их детерминированными. **−** `2×` перерасход токенов |
| **2. Fission-AI OpenSpec** ([OpenSpec](https://github.com/Fission-AI/OpenSpec)) | Brownfield SDD (`spec-anchored`: `specs/` + дельты `ADDED/MODIFIED/REMOVED` + `archive`) | `58K–92K` | Средне: домены без графа кода | **Средняя:** грузит целые `.md` доменов | Средняя (`84%` merge на сильных LLM, `16%` брака) | **Берём:** механику дельт и `archive` в канон. **−** Проверяет заголовки `.md`, а не полноту ветвлений |
| **3. AWS Kiro** ([kiro.dev](https://kiro.dev/docs/specs/)) | Коммерческая SDD IDE (EARS + `Quick Spec` + `unchanged behavior` + `waves`) | `60K–110K` | Средне: `.kiro/steering` + спеки фич | **Средняя:** lock-in моделей закрытой IDE | Средняя: авто-запуск тестов по хукам без защиты оракула | **Берём:** `Quick Spec`, поле багфикса `unchanged behavior` и волны `waves`. **−** Закрытая IDE |
| **4. BMAD Method** ([repo](https://github.com/bmad-code-org/bmad-method)) | Ролевая agile-методология (`PM→Arch→Dev→QA`) | `150K–400K+` | Плохо для итеративных правок большого кода | **Очень низкая:** потеря смысла на пересказах | Низкая: нет машинных гейтов и блокировок ФС | **Берём:** только идею масштабирования глубины процесса. **−** Сжигает бюджет на ролевую прозу |
| **5. Tessl** ([launch](https://tessl.io/blog/tessl-launches-spec-driven-framework-and-registry)) | `Spec-as-Source` + реестр `10 000+` спек внешних OSS-библиотек | Высокий при регенерации (`2–5К` на карточку API) | **Неприменимо** как генератор legacy-баз | **Средняя на внешних API**, низкая на кодогенерации | Ловушка MDD + недетерминизм LLM | **Берём:** компактные внешние спеки библиотек против галлюцинаций API. **−** Непригодна как генератор прод-кода |
| **6. Taskmaster** ([repo](https://github.com/eyaltoledano/claude-task-master)) | Лёгкий JSON-менеджер задач из PRD (`tasks.json` + MCP/CLI) | `15K–40K` | Слабо: нет архитектуры и графа кода | **Средняя:** простой JSON понятен малым LLM | Низкая: нет верификатора и оракулов | **+** Доказывает удобство лёгкого JSON задач. **−** Только трекер подзадач |
| **7. mini-SWE-agent + Ralph loop** ([mini-swe](https://github.com/swe-agent/mini-swe-agent), [ralph](https://ghuntley.com/ralph/)) | Ультраминимальный bash-харнес (~`100` LOC, `>74%` SWE-bench) + внешний цикл | **`10K–35K`** на атомарный фикс | Средне (без графа уходит в `grep`) | **Средне-высокая** без лишних схем тулов | Зависит от внешнего гейта и песочницы | **Берём:** нулевой процессорный жир и цикл до зелёного оракула внутри 5-контурного sandbox |
| **8. Consort** ([`arXiv:2609.09671`](https://arxiv.org/html/2609.09671v1)) | Enforced TDD SDD + ветки живой БД | `50K–90K` | Средне | **Выше среднего** | **Высокая:** `Tests immutable` + живая БД | **Берём:** физическую неизменяемость тестов для кодера (`RO Trust Zone`) |
| **9. Codified Context** ([`arXiv:2602.20478`](https://arxiv.org/abs/2602.20478)) | 3-ярусная память (Hot / Domain Agents / Cold Specs, `108K LOC` C#) | `30K–65K` | Хорошо | **Средняя:** холодные спеки по ~500 строк велики | Средне-высокая: линтер ссылок при старте | **Берём:** 3-ярусную маршрутизацию и Drift Guardian |
| **10. Aider (Architect + RepoMap)** ([repomap](https://aider.chat/docs/repomap.html)) | Терминальный агент (`Tree-sitter` + `PageRank` + 2 модели) | `25K–126K` (экономия до **`14×`**) | **Хорошо (`100+` языков)** | **Высокая в паре `Architect → Editor`** | Средняя: нет спек и защиты тестов | **Берём:** разделение `Architect / Blind Editor` и бюджет карты `~1k` ток. |
| **11. Agentless + RepoGraph** ([`arXiv:2407.01489`](https://ar5iv.labs.arxiv.org/html/2407.01489)) | Безагентный 3-шаговый конвейер (`Localize → Repair → Validate`) | **`18K–47K`** | Хорошо на уровне кода | **Высокая** на узких шагах | Средне-высокая | **Берём:** отказ от свободного блуждания в пользу узких детерминированных фаз |
| **12. Подключаемые графы (`CBM`, `CodeGraph`, `Graphify`, `CodePrizm`)** | Готовые внешние графы кода/доков и валидированный batch-аудит | **`200–1 500` ток./запрос** (экономия `10×–120×`) | **Отлично (`164` яз., PHP/Laravel, Leiden-граф доков)** | **Отлично через `locator` / CLI**, опасно при глобальном MCP | Дают `affected tests`, `data-flow` и batch-аудит | **Основа Трека А!** Сами по себе видят только `As-Is`, поэтому сцепляются с контрактами `sf` (`To-Be`) |
| **13. Factory.ai / Cognition Devin** | Облачные закрытые фабрики (`Missions`, `Managed Devins`) | Дорогая подписка | Хорошо | Закрытый облачный стек | Зависит от CI клиента | Закрытый проприетарный контур без наших локальных формальных контрактов |
| **14. GitHub `gh-aw` / OpenHands** ([gh-aw](https://github.com/github/gh-aw)) | Event-driven раннеры с `Safe Outputs` | `80K–250K` | Средне-хорошо | Средняя (`Devstral-24B`, `Qwen3`) | **Высокая изоляция записи** в `gh-aw` | **Берём:** паттерн `Agent Proposes → Privileged Gate Applies` |
| **15. Текущая `sf v0.2.0`** (`f8cb406`) | Пассивный CLI + Markdown-скиллы (`state/events` в `0/77`) | `254K` новых (`7.3M` кэша), `~25K` налог старта | **Слабо** (POSIX-only запись, `45` доков в индексе) | **Низкая:** тонет в прозе `go-to-task` | Средняя: SHA-256 в `23/75`, `0` оракулов, `23/29` без `approvals` | Отличный скелет схем, журнала и inbox, требующий разблокировки `F00–F0` |
| **16. Целевая `sf v3.0` (`Трек А + Трек Б`)** | **Субагенты и готовые графы среды ⋈ Тонкое ядро контрактов `arch` (`*.flow.json`, `Oracle-First`, `Diff-Mutation`)** | **`6K–18K` за задачу (`~9–10K` багфикс Laravel, `≤2K` envelope)** | **Универсально (`100K–10M+ LOC`, Linux/macOS/Windows)** | **Максимальная:** 1-tool навигатор + `Winninger Verifier` (`54.5%→90.9%`) | **`escape_rate → 0%`:** `Red` оракул + `RO Trust Zone` + DMN + `Diff-Mutation` | Синергия готовой экосистемы без самописных MCP и без раздувания `arch` CLI |
