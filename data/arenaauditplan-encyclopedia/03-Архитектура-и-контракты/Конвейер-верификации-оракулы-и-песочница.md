# Конвейер верификации, `Infection PHP`, безопасность MCP, 5-контурная песочница и система `Evals`

> [!abstract] Кратко
> Синтез конвейера приёмки `sf v3.0` с практиками [Безопасность MCP и инструментов.md](<../../machinedocs-encyclopedia/Практики/Безопасность MCP и инструментов.md>) и [Evals и метрики агентной разработки.md](<../../machinedocs-encyclopedia/Практики/Evals и метрики агентной разработки.md>): **6 независимых барьеров приёмки**, точный рецепт инкрементальных дифф-мутаций для `PHP/Laravel` (`Infection --git-diff-lines` с `PCOV`), строгая схема `verification.json v1.0`, матрица защиты MCP-периметра, 5-контурный sandbox и защита метрик от накрутки (`metric gaming`).

## 1. Шесть независимых барьеров приёмки и дифф-мутации `Infection PHP`

1. **`Oracle-First` (`Red` до правки кода):** `oracle-keeper` создаёт проверяемый тест по `AC-N`, который обязан упасть (`red_exit_code != 0`) на базовом `HEAD` — тавтологии `assert True` отсекаются мгновенно.
2. **Физическая изоляция `RO Trust Zone`:** на шаге `implementer` каталоги `tests/**`, `doc/architecture/**` и конфиги гейтов закрыты от записи правами субагента и RO-маунтами контейнера/`bwrap`.
3. **Графовый выбор регрессионных тестов + меркл-контроль атомарности:** `codegraph affected` / `cbmemory detect_changes --scope tests` включает все затронутые по графу тесты; на `read_only`-ветках проверяется побайтная неизменность дерева (`state_unchanged_on_disk: true`).
4. **Независимый пофункциональный ревьюер (`Winninger Verifier`, `54.5% → 90.9%`):** другая модель в чистом окне (при `shared_agent_board: false`!) проверяет каждую изменённую функцию отдельно по 4 вопросам и дополнительно проверяет дифф тестов на отсутствие удалённых/ослабленных `assert`, `skip` и заниженных порогов.
5. **Взаимная страховка «Таблицы решений DMN `*.flow.json` ⋈ `Diff-Scoped Mutation Gate`»:**
   - Таблица решений `*.flow.json` (`0 gaps / 0 overlaps`) страхует от *ненаписанной ветки*, а дифф-мутатор — от *слабого ассерта* на написанных строках.
   - **Верифицированный контур для `PHP / Laravel` владельца ([Infection 0.26+](https://infection.github.io/2022/01/10/whats-new-in-0.26.0/)):** используется расширение **`PCOV`** вместо `Xdebug` и флаг `--git-diff-lines` (требует полной истории `fetch-depth: 0`), мутирующий **только затронутые диффом строки** и сокращающий прогон на legacy-проекте с `20+` минут до **`1–3` минут**:
     ```bash
     php -d pcov.enabled=1 vendor/bin/infection \
       --git-diff-lines --git-diff-base=main \
       --min-msi=80 --min-covered-msi=90 --threads=4 --no-interaction
     ```
   - Аналоги для полиглот-стека: Python `mutmut`, TS/JS `npx stryker run --incremental` (`94%` переиспользования кэша), C# `dotnet stryker --since`, Rust `cargo mutants --in-diff`, JVM `PIT -DwithHistory`.
6. **Детерминированные `arch analyze / converge` + машинный блокер `approvals` владельца** поверх строгой схемы `verification.json v1.0` (`result ∈ {"pass", "fail", "not_run"}`, где `not_run ≠ pass`, обязательные `checked_revision` и `snapshot_sha256`).

## 2. Безопасность MCP-инструментов и 5 границ песочницы (`OWASP MCP + 5-Boundary Sandbox`)

По модели угроз [OWASP MCP Security Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/MCP_Security_Cheat_Sheet.html) и [Безопасность MCP и инструментов.md](<../../machinedocs-encyclopedia/Практики/Безопасность MCP и инструментов.md>):
- **Контроль 8 поверхностей атак MCP:** (1) пиннинг версий/хешей внешних бинарников в `.sf/providers.yaml` против *tool description poisoning* и *rug pull*; (2) разделение `read-only` графовых MCP и `write`-инструментов против *cross-server read→write escalation*; (3) трактовка текста внешних Jira-тикетов и ответов тулов как **недоверенных данных** (*indirect prompt injection*); (4) запрет полагаться на `readOnlyHint`/`destructiveHint` как на авторизацию — блокировка обеспечивается на уровне исполнителя и ОС.
- **Пять физических границ песочницы для автономных циклов (`Ralph loop`):** `Compute` (лимиты CPU/RAM/PIDs) · `Filesystem` (RW только `worktree`, RO на `tests/**`, `0` доступа к `~/.ssh`, `~/.aws`) · `Network` (**строгий `egress allowlist`** — блок эксфильтрации и SSRF на внутренние/metadata IP) · `Identity` (непривилегированный UID без `git push`) · `Data & Secrets` (короткоживущие токены вне окружения воркера, уникальные `APP_PORT` и БД на каждый `worktree`).
- **Протокол `Cold Resume`:** JSON-флаги `"passes": false` + `arch task replay` + принудительный входной smoke-прогон по всем ранее принятым шагам + `Circuit Breaker` при `2×` одинаковой ошибке гейта.

## 3. Трёхконтурная система `Evals`, защита от накрутки метрик и телеметрия `DORA / OpenTelemetry`

По стандарту [Evals и метрики агентной разработки.md](<../../machinedocs-encyclopedia/Практики/Evals и метрики агентной разработки.md>) любые изменения промптов, моделей, скиллов и правил `sf v3.0` проверяются в **3 контурах** (`Task benchmark` со скрытым оракулом → `Regression eval` до влития изменений конфигов → `Production monitoring` после выкатки) с защитой от *vanity metric gaming*:

| Ложная метрика (как её взламывают) | Защищённая продуктовая метрика `sf v3.0` | Целевой ориентир (SLO) |
|---|---|---|
| `Green CI` / `Coverage %` (удаление ассертов, пустой прогон строк) | `Defect Escape Rate` при `RO Trust Zone` + `Diff-MSI ≥ 80–90%` + скрытых тестах | **`→ 0%`** на регрессионном наборе |
| «Дешёвые токены за шаг» (урезание проверок и рост переделок) | Полная стоимость **принятого с первого раза и не откаченного за 7/30 дней** изменения | **`≤ 10–12K` ток.** на микро-багфикс; `first_pass_green ≥ 85%` |
| Количество PR / скорость генерации (дробление тривиальных правок) | Сквозные метрики **DORA** (`lead time`, `change failure rate`, `recovery time`) + время ревью владельца | Снижение `review burden` при `0` инцидентов |

Сквозная трассировка связывает в `events.jsonl` (совместимо с `OpenTelemetry GenAI`): `task_key → session_id → role → model/prompt/tool_version → commit_sha → verification_digest → deployment/incident`.
