# Этап `F00` (День 1, `1–2 дня`): Развёртывание графов кода, `Graphify` и ролевых субагентов без правки `arch` CLI

> [!abstract] Паспорт этапа `F00`
> - **Трек:** `track-a-env` (**`0` строк изменений в `doc/tools/arch/`**).
> - **Закрываемые проблемы:** `PROB-01, PROB-04, PROB-05, PROB-06, PROB-10, PROB-20 (обход migrate), PROB-22 (обход wsl), PROB-24, PROB-30, PROB-31, PROB-32, PROB-33` (см. [[04-Реестр-проблем-и-требований/Мастер-реестр-проблем-PROB-01-PROB-38]]).
> - **Реализуемые требования:** `R7, R8, R12, R13, R14, R20, R21, R22` (см. [[04-Реестр-проблем-и-требований/Рекомендации-R1-R23-и-открытые-вопросы-владельцу]]).
> - **Зависимости:** нет (выполняется в День 1 параллельно или до `F0`).

## Задачи этапа (готовые шаблоны для `arch task new`)

### TASK-F00-01 — Установка MIT-графов кода (`colbymchenry/codegraph`, `codebase-memory-mcp`), `RTK` и `Graphify`
- **Тип / Профиль / Риск:** `chore` (`change`) · `quick` · `low`
- **Входы и ссылки:** [[02-Исследования-и-инструменты/Подключаемые-графы-кода-аудит-и-компрессоры]], `PROB-04`, `PROB-31`, `PROB-33`, `R8`, `R20`
- **Область работ (`scope.in`):**
  1. Установить бинарники MIT-инструментов `colbymchenry/codegraph`, `codebase-memory-mcp` и `rtk`; проиндексировать `sf` и рабочий репозиторий владельца (`PHP/Laravel`), сохранив переносимый `.codebase-memory/graph.db.zst`.
  2. Установить `graphifyy` (`uv tool install graphifyy`) и собрать граф знаний по `doc/architecture/` и `data/` без модификации `arch` CLI.
  3. Проверить отсутствие `GitNexus` (`PolyForm NC`) в коммерческих контурах без лицензии и зафиксировать разграничение имён `CodePrizm / CodePrism`.
- **Критерии приёмки (`AC`):**
  - `AC-1`: `codegraph_explore` и `codebase-memory-mcp cli search_graph` возвращают символ, вызовы и затронутые тесты за `<2 с` при объёме ответа `≤1 500` токенов.
  - `AC-2`: семантический запрос к графу `Graphify` по `doc/architecture/` находит нужный контракт без чтения монолитов `136 КБ`.

### TASK-F00-02 — Развёртывание 7 ролевых субагентов со строгим `MCP Scoping` в `OpenCode / Kilo / Claude`
- **Тип / Профиль / Риск:** `feature` (`change`) · `standard` · `medium`
- **Входы и ссылки:** [[02-Исследования-и-инструменты/Субагенты-и-оркестрация-в-средах-OpenCode-Kilo-Claude]], `PROB-01`, `PROB-06`, `PROB-30`, `PROB-31`, `PROB-32`, `R20`, `R21`
- **Область работ (`scope.in`):**
  1. Разместить проектные конфиги ролей `orchestrator`, `locator`, `planner`, `oracle-keeper`, `implementer`, `verifier`, `docs-keeper` (`opencode.jsonc`, `kilo.jsonc`, `.claude/agents/*.md`).
  2. Явно прописать `model: ...`, `temperature: 0.1` и `steps: 12` для `implementer`, а для `verifier` назначить **другую модель** без истории рассуждений кодера.
  3. Изолировать графовые MCP только внутри `locator` и `verifier` (`inline mcpServers` в Claude / per-agent `deny` в OpenCode/Kilo), оставив `0` графовых MCP-схем у `implementer`, и проверить обход `OpenCode #6396`.
- **Критерии приёмки (`AC`):**
  - `AC-1`: лог запроса субагента `implementer` содержит `0` описаний тулов `codegraph` / `cbmemory` и явно использует дешёвую модель (не наследуя модель родителя).
  - `AC-2`: попытка `implementer` изменить файл в `tests/**` или выполнить `git push` блокируется правами среды.

### TASK-F00-03 — Тонкий маршрутизирующий скилл `sf-go` (`metadata-only`) и лестница `Graph-First`
- **Тип / Профиль / Риск:** `refactor` (`change`) · `quick` · `low`
- **Входы и ссылки:** [[02-Исследования-и-инструменты/Субагенты-и-оркестрация-в-средах-OpenCode-Kilo-Claude]], `PROB-05`, `PROB-20`, `PROB-24`, `PROB-32`, `R7`, `R21`
- **Область работ (`scope.in`):**
  1. Создать компактный проектный скилл `.kilo/skills/sf-go/SKILL.md` (без shell-инъекций `` !`cmd` ``, не работающих в проектном каталоге Kilo), заменяющий загрузку `~25 000` токенов прозаических скиллов в одно окно.
  2. Встроить обязательный вызов `arch task migrate <key>` сразу после `arch task new` (обход `PROB-20` до завершения `F0`) и правило `Graph-First Fallback-Chain`.
- **Критерии приёмки (`AC`):**
  - `AC-1`: стартовый пакет сессии до первой локализации кода весит `≤2 500` токенов вместо `~25 000`.
  - `AC-2`: созданная через скилл `sf-go` карточка немедленно получает валидные `state.json` и `events.jsonl`.

### TASK-F00-04 — Настройка Windows `worktree`-окружения (`.kilo/setup-script.ps1`) и обход `fcntl` через `wsl`
- **Тип / Профиль / Риск:** `chore` (`change`) · `quick` · `medium`
- **Входы и ссылки:** [[02-Исследования-и-инструменты/Субагенты-и-оркестрация-в-средах-OpenCode-Kilo-Claude]], `PROB-10`, `PROB-22`, `PROB-32`, `R22`
- **Область работ (`scope.in`):**
  1. Добавить `.kilo/setup-script.ps1` для `Kilo Agent Manager` на Windows: уникальное смещение `PORT` от пути `WORKTREE_PATH`, копирование всех `.env` (включая вложенные монорепо-пакеты), распаковка `.codebase-memory/graph.db.zst`, запрет общего `git stash`.
  2. Настроить правило сохранения/мержа ветки **до** закрытия `worktree` в UI Kilo (защита от потери коммитов) и проброс write-вызовов `arch` через `wsl python3` до закрытия `TASK-F0-02`.
- **Критерии приёмки (`AC`):**
  - `AC-1`: два параллельных `worktree` в `Kilo Agent Manager` на Windows стартуют без конфликта портов и `.env`, а тестовый багфикс по Плейбуку A укладывается в `≤12 000` токенов суммарно.
