# Этап `F3` (`2 недели`): 5-контурная песочница, волны `worktree`, маршрутизация моделей и `Cold Resume`

> [!abstract] Паспорт этапа `F3`
> - **Трек:** `both` (безопасное масштабирование на параллельные волны и длинные автономные смены).
> - **Закрываемые проблемы:** `PROB-06, PROB-10, PROB-16, PROB-26, PROB-27`.
> - **Реализуемые требования:** `R13, R14, R15, R16` + закрытие конфликта `CONF-08` (`README` vs `worktree.md`).
> - **Зависимости:** `F0–F2`.

## Задачи этапа (готовые шаблоны для `arch task new`)

### TASK-F3-01 — Развёртывание 5-контурного sandbox'а с `egress allowlist` для автономных прогонов
- **Тип / Профиль / Риск:** `feature` (`change`) · `full` · `critical`
- **Входы и ссылки:** [[03-Архитектура-и-контракты/Конвейер-верификации-оракулы-и-песочница]], `PROB-26` (`D-11`), `R15`
- **Область работ (`scope.in`):**
  1. Оформить воспроизводимый профиль песочницы (Devcontainer / Docker / WSL2 + `bwrap` + `Kilo /sandbox`) по 5 границам: лимиты CPU/RAM/PIDs, RW только в `worktree` задачи (RO на `tests/**` и `0` доступа к `~/.ssh`, `~/.aws`), строгий сетевой **`egress allowlist`**, непривилегированный UID без `git push`, изоляция секретов.
  2. Обновить `VIEW-security` (`doc/architecture/system/security.md`) до `implemented: true`.
- **Критерии приёмки (`AC`):**
  - `AC-1`: проверочный тест внутри песочницы подтверждает физическую блокировку `curl https://example.com`, чтения `~/.ssh` и записи в `tests/**` от имени кодера.

### TASK-F3-02 — Топологические волны `waves`, per-child `git worktree` и устранение конфликта `README ↔ worktree.md`
- **Тип / Профиль / Риск:** `feature` (`change`) · `standard` · `high`
- **Входы и ссылки:** [[02-Исследования-и-инструменты/Субагенты-и-оркестрация-в-средах-OpenCode-Kilo-Claude]], [worktree.md](<../../../worktree.md>), `PROB-10`, `R14`, [[06-Консилиум-и-конфликты/Реестр-конфликтов-и-решений|CONF-08]]
- **Область работ (`scope.in`):**
  1. Реализовать расчёт непересекающихся волн подзадач (`arch task waves <parent_key>`) на основе `allowed_edit_spans` и графа вызовов (`0` пересечения файлов и `1-hop` соседей внутри одной волны) и команды управления per-child ветками/`worktree` для интеграции с `Kilo Agent Manager` и `OpenCode`.
  2. Гармонизировать `README.md` и `worktree.md` §4.6: локальный `python -m arch gate` — самодостаточный обязательный гейт; серверная защита веток — опциональный дублирующий рубеж.
- **Критерии приёмки (`AC`):**
  - `AC-1`: две подзадачи с пересекающимися файлами автоматически разносятся в `Wave 1` и `Wave 2`, а параллельная волна из 3 подзадач мержится без конфликтов.

### TASK-F3-03 — Исполняемая маршрутизация ролей и моделей (`CAP-role-model-routing` → `implemented: true`)
- **Тип / Профиль / Риск:** `feature` (`change`) · `standard` · `medium`
- **Входы и ссылки:** [[02-Исследования-и-инструменты/Субагенты-и-оркестрация-в-средах-OpenCode-Kilo-Claude]], `PROB-06`, `R13`, `OQ-04`
- **Область работ (`scope.in`):**
  1. Связать декларативную таблицу слотов моделей (`strong / balanced / weak-fast`) в `.sf/providers.yaml` с генератором/валидатором конфигов сред (`opencode.jsonc`, `kilo.jsonc`, `.claude/agents/`) и автоподбором слота по `risk × complexity` задачи.
- **Критерии приёмки (`AC`):**
  - `AC-1`: валидатор конфигов сред ловит любой субагент без явно заданного поля `model` или без лимита `steps`.

### TASK-F3-04 — Протокол `Cold Resume` (`passes: false`, `task replay` + обязательный входной smoke-прогон)
- **Тип / Профиль / Риск:** `feature` (`change`) · `standard` · `high`
- **Входы и ссылки:** [[01-Аудит-текущей-системы/Моделирование-сценариев-и-режимы-отказа-F1-F14]], [[03-Архитектура-и-контракты/Конвейер-верификации-оракулы-и-песочница]], `PROB-27` (`D-12`), `R16`
- **Область работ (`scope.in`):**
  1. Реализовать команду `arch task resume <task_key>`, которая восстанавливает `state.json` через `replay`, прогоняет входной smoke-набор по всем подзадачам/кейсам с `"passes": true` и выдаёт капсулу ровно для первого элемента с `"passes": false`.
- **Критерии приёмки (`AC`):**
  - `AC-1`: имитация аварийного обрыва (`kill -9`) на подзадаче `#3` из `5` проходит `arch task resume` без потери закрытых `#1..#2` и без перечитывания всего дерева задач.

### TASK-F3-05 — Онлайн-предохранитель `Circuit Breaker` на базе `session_audit`
- **Тип / Профиль / Риск:** `feature` (`change`) · `quick` · `medium`
- **Входы и ссылки:** [[01-Аудит-текущей-системы/Рентген-репозитория-и-ядра-CLI]], `PROB-16`, `R16`
- **Область работ (`scope.in`):**
  1. Перевести `session_audit.py` из чисто посмертного отчёта в активный сторож итерации: автоматическая остановка цикла при `2×` подряд одинаковой ошибке гейта, превышении лимита токенов на шаг или переходе `validity` в `stale/conflicted`.
- **Критерии приёмки (`AC`):**
  - `AC-1`: искусственное зацикливание падающего теста останавливает автономный цикл на 2-м повторе с записью причины в `events.jsonl`.
