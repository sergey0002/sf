# Проверяемые требования `R1–R23` с критериями приёмки и открытые вопросы владельцу `OQ-01..OQ-06`

> [!abstract] Кратко
> Сводный нормативный перечень **23 инженерных требований (`R1..R23`)** с машинными критериями приёмки (`AC`) и **6 открытых вопросов владельцу (`OQ-01..OQ-06`)**, синхронизированный с [[04-Реестр-проблем-и-требований/Мастер-реестр-проблем-PROB-01-PROB-38]] и разнесённый по этапам `F00..F4`.

## 1. Нормативная матрица рекомендаций `R1..R23`

| Код | Этап и Трек | Требование | Проверяемый критерий приёмки (`AC`) |
|---|---|---|---|
| **`R1`** | `F0` (Трек Б) | Подключить `task_record.py` в `schema.py` (`task new/init`) и мигрировать все `77` задач | `77/77` задач имеют валидные `state.json`, `events.jsonl` и непустой `intent_digest`; мутация `intent` без `revise` блокируется гейтом |
| **`R2`** | `F0` (Трек Б) | Кроссплатформенный файловый лок в `fs_atomic.py` + `python -m arch gate` без `bash/tar` | Полный тест-набор и write-команды `arch` проходят на Linux и нативном Windows (PowerShell) с `exit 0` |
| **`R3`** | `F0` (Трек Б) | Жёсткий блокер `approvals` и запрет `owner == "unset"` при `arch task close` | Попытка закрыть задачу `risk ≥ medium` с `approvals: []` возвращает `exit != 0` с JSON-ошибкой `APPROVAL_REQUIRED` |
| **`R4`** | `F0` (Трек Б) | Строгая JSON Schema `verification.json` (`v1.0`: `result ∈ {pass, fail, not_run}`) | `not_run` и проза не проходят гейт закрытия; ревизия `checked_revision` и `snapshot_files` обязательны |
| **`R5`** | `F0` (Трек Б) | Починка `body_validation.py`, `document.schema.json`, `paths.yaml` (`architecture-delta`), 8 локальных путей, дубля манифеста, `UI-0032-0005`, `seesionaudit.md`, `data/README.md` и включение `arch scan` в `gate` | `python -m arch gate` (включающий `validate`, `scan`, `index check`, `docs paths --check`, `check-links`) зелёный с реальной валидацией тел (`0/45` нарушений + негативные unit-тесты!) |
| **`R6`** | `F1` (Трек Б) | Профиль `Quick Spec` (`task.json ≤ 1 КБ`) + обязательное поле `unchanged_behavior` для багфиксов | Создание и прохождение микро-багфикса занимает `≤ 6` шагов без ручного заполнения десятков полей |
| **`R7`** | `F00/F1` (Оба) | Пакетный `Context Compiler` (`arch context pack <task_key> --role <role>`) + фильтр `implemented: true` + `metadata-only` скиллы | Стартовый контекст роли не превышает `3.2k–6k` ток. (`−80%` от `25k`); секции не падают по `SECTION-TOO-LARGE` |
| **`R8`** | `F00/F1` (Трек А) | Подключение MIT-графов кода (`colbymchenry/codegraph` + `codebase-memory-mcp`) и графа доков `Graphify` | Локализация контекста в репо `3 500+` файлов тратит `≤ 1.5k–2k` ток. без чтения целых файлов |
| **`R9`** | `F1` (Трек Б) | Сжатие `13` типов `task-conf` в `4` базовых конвейера (`observe/specify/change/release`) + `stageN/workpack.json` | Устранено дублирование `plan-tier` между Python и YAML; `workpack.json` валидируется схемой |
| **`R10`** | `F1` (Оба) | Протокол `Oracle-First` (`Red` до кода) + защита `RO Trust Zone` на `tests/**` для роли `implementer` | Тест обязан упасть на чистом `HEAD` до правки кода; попытка кодера изменить `tests/**` отклоняется правами |
| **`R11`** | `F2` (Трек Б) | Канон `*.flow.json` (DMN `UNIQUE/COLLECT` `0 gaps / 0 overlaps`, `flows.index.json`, `flow-delta.json`) + `Validity L1` (`task snapshot/audit/impact`) | Коллизия `UI-0030` vs `UI-0029` ловится автоматически; `arch docs flow validate/build` зелёные на реальных флоу `sf` |
| **`R12`** | `F00/F2` (Оба) | Независимый пофункциональный ревьюер (`Independent Verifier` по Winninger) + детерминированные `arch analyze / converge` | `verifier` работает на другой модели без истории чата автора; `analyze` сверяет биекцию `AC ↔ CASE ↔ diff` |
| **`R13`** | `F00/F3` (Оба) | Исполняемая маршрутизация ролей и моделей (`CAP-role-model-routing` → `implemented: true`) | Слабая модель исполняет только ограниченные `implementer`-шаги с явно заданными `model`, `temperature: 0.1` и `steps: 12` |
| **`R14`** | `F00/F3` (Оба) | Топологические волны `waves` и изоляция `git worktree` на каждую подзадачу | Параллельные подзадачи одной волны работают в отдельных ветках/worktree без гонок портов, `.env` и БД |
| **`R15`** | `F3` (Оба) | Пятиконтурный sandbox (`compute / FS / network egress allowlist / identity / secrets`) | Несанкционированный сетевой запрос и чтение `~/.ssh` изнутри тестового прогона физически блокируются |
| **`R16`** | `F3` (Оба) | Протокол `Cold Resume` (`passes: false` в JSON + `arch task replay` + входной smoke-прогон + `Circuit Breaker`) | Искусственный обрыв серии подзадач на середине восстанавливается одной командой без потери прогресса и без перечитывания корпуса |
| **`R17`** | `F4` (Оба) | Инкрементальный `Diff-Scoped Mutation Gate` (`Infection`, `mutmut`, `Stryker`, `cargo-mutants`, `PIT`) + сжиматели `RTK / Headroom` | На `high-risk` задачах выживший в изменённых строках мутант блокирует закрытие задачи (`MSI ≥ 90%` на диффе) |
| **`R18`** | `F4` (Трек Б) | Обратный контур `tracker_outbox.py` в паре с `tracker_inbox.py` | События смены фазы и закрытия задачи идемпотентно формируют пакет синхронизации во внешний трекер |
| **`R19`** | `F1/F4` (Оба) | Команда/шаблон `sf init --external` (`<15 мин`) + регрессионный `eval-suite` и живой пилот на внешнем репозитории | Пройдены `10–20` реальных продуктовых задач (вкл. `PHP/Laravel`) со сбором целевых SLO (`escape_rate`, `tokens/step`, `first_pass_green`) |
| **`R20`** | `F00` (Трек А) | Строгий `MCP Scoping` (`0` графовых MCP у `implementer`, `inline mcpServers` у `locator/verifier`) + проверка MIT-лицензий | В запросах слабой модели `implementer` `0` токенов уходит на схемы графовых MCP-тулов |
| **`R21`** | `F00` (Трек А) | Проектные конфиги субагентов `opencode.jsonc`, `kilo.jsonc`, `.claude/agents/*.md` и скилл `sf-go` | Все 7 ролей фабрики развёрнуты в среде с явными allowlist/denylist и работают без правки `arch` CLI |
| **`R22`** | `F00` (Трек А) | Скрипт `.kilo/setup-script.ps1` на Windows + обход граблей `OpenCode #6396` и `Kilo #13827` | Параллельные `worktree` в `Kilo Agent Manager` на Windows получают уникальные `PORT`, скопированные `.env` и сохранённые ветки |
| **`R23`** | `F4` (Трек А) | Регламент периодического независимого batch-аудита через `Green Olive CodePrizm` | Валидированные findings с line-level ссылками конвертируются в карточки типа `audit` и сверяются с `doc/architecture/` |

## 2. Открытые вопросы, требующие решения владельца (`OQ-01..OQ-06`)

1. **`OQ-01` (Единый канон Манифеста — `PROB-36`):** какой из двух расходящихся на `23 КБ` файлов оставить единственным каноном — корневой `Манифест агентной software factory.md` (с заменённым коротким резюме `SYS-simple-factory` в `doc/architecture/system/`) или `doc/architecture/system/manifest.md` (с переносом принципов `15/15a`, очисткой `33` `[[wikilinks]]` и оставлением в корне короткого указателя)?
2. **`OQ-02` (Язык заголовков шаблонов в `ARCH-contract` §5.5 — `PROB-34`):** утверждаем ли официально **русскоязычные заголовки `##`** из `doc/architecture/schemas/bodies/*.json` как единственный стандарт корпуса с синхронным переводом английских шаблонов в `ARCH-contract` §5.5A–J?
3. **`OQ-03` (Исторические битые ссылки в закрытых `UI-0001..0007` — `PROB-38`):** нормализовать `37` относительных путей `../../../` в `project_context_refs` закрытых ранних карточек одноразовой миграцией или зафиксировать правило иммутабельности закрытых архивных задач в валидаторе?
4. **`OQ-04` (Приоритетная основная агентная среда владельца на Windows — `F00`):** какая связка является основной на рабочей Windows-машине прямо сейчас (`Kilo Code + Agent Manager`, `OpenCode` или `Claude Code`) и какие конкретно провайдеры/модели назначить на слоты `strong (planner/verifier)` и `cheap/weak (locator/implementer)`?
5. **`OQ-05` (Первый живой внешний продуктовый полигон — `F1/F4`):** запускаем ли первый продуктовый вертикальный срез `F1` и пилот `F4` сразу на рабочем репозитории `PHP / Laravel B2B CRM` владельца (или другом целевом продуктовом репо)?
6. **`OQ-06` (Политика `approvals` для исторических `23/29` закрытых задач — `PROB-21`):** проставить ли ретроспективный `owner approval` пакетной миграцией для уже принятых в `master` `23` закрытых задач `UI-*` или применять жёсткий блокер только к задачам со `schema_version >= "1.0"`?
