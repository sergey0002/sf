# Контекст-инженерия для AI-агентов: AGENTS.md, CLAUDE.md, steering

Конституция Spec Kit и steering-файлы Kiro — частные случаи более общего явления:
**контекст-инженерия** — проектирование того, что агент читает на старте сессии.
К 2026 году сложился стандарт: `AGENTS.md` как кросс-инструментальная база,
инструмент-специфичные файлы как оверрайды, спеки — как контекст конкретной задачи.

## 1. Ландшафт файлов инструкций

| Файл | Инструменты | Роль |
|---|---|---|
| **AGENTS.md** | Claude Code, Codex CLI, Cursor, Aider, Devin, Copilot, Gemini CLI, Windsurf, Amazon Q, Zed | Универсальный стандарт инструкций проекта |
| **CLAUDE.md** | Claude Code | Нативный формат Anthropic; читается как fallback AGENTS.md |
| **.cursor/rules/*.mdc** | Cursor | Правила с `alwaysApply` и glob-скоупом по путям |
| **.github/copilot-instructions.md** | Copilot | Инструкции + path-scoped `.github/instructions/*.instructions.md` |
| **.clinerules/** | Cline | Папка правил; AGENTS.md — fallback |
| **.kiro/steering/** | Kiro | Контекст проекта: стек, стандарты, структура |
| **.specify/memory/constitution.md** | Spec Kit | Конституция — принципы проекта |
| **SKILL.md** | Claude Code и др. | Процедуры, загружаемые по требованию (не постоянный контекст) |

**Рекомендуемая архитектура (консенсус 2026):**
1. Один `AGENTS.md` в корне — всё инструмент-независимое (команды, архитектура, конвенции).
2. `CLAUDE.md` — одна строка `@AGENTS.md` (import) или symlink + только Claude-специфичное.
3. Path-scoped правила (`.claude/rules/`, `.cursor/rules/`) — только для конкретных типов файлов.
4. Процедуры (релиз, миграция) — в skills/slash-командах, а не в постоянном контексте.
5. Спека текущей фичи — в `spec.md` ветки, а не в перепечатываемом промпте.

## 2. Дисциплина размера: правило 150–200 строк

- Всегда загружаемые файлы должны быть **< 200 строк** (консенсус: 150–200). Длиннее —
  падает adherence: эффект «lost in the middle», агент игнорирует середину.
- Codex CLI: лимит цепочки инструкций `project_doc_max_bytes` = 32 KiB по умолчанию;
  при превышении файлы просто не добавляются.
- Исследование 2026 (138 репозиториев): **разработчиком написанные** AGENTS.md улучшают
  успех задач агентов на ~4% и снижают баги на 35–55%; **сгенерированные LLM** —
  снижают успех и увеличивают стоимость инференса на 20%+.
- Проверка загрузки: `/context` в Claude Code показывает список Memory files —
  если файла нет в списке, агент его буквально не видит.

**Что включать:**
- Точные команды сборки/тестов/линта (агент их исполняет автоматически)
- Карта архитектуры: ключевые каталоги, критичные файлы
- Конвенции, отклоняющиеся от дефолтов («проект использует Result-паттерн — см. src/utils/result.ts»)
- Ограничения: безопасность, границы производительности, запрещённые паттерны
- Правила тестирования: как запускать, требования к покрытию
- Антипаттерны: что пробовали и отклонили, с обоснованием

**Что НЕ включать:**
- Стандартные конвенции языка (это работа линтера)
- «Пишите чистый код» и прочие платонические советы
- Исчерпывающие листинги файлов (агент выведет из кода)
- Детали модулей (грузить по требованию через skills/поиск)
- Секреты — никогда
- Копии документов (устареют) — только ссылки

## 3. Слои контекста (полный стек 2026)

| Слой | Механизм | Что живёт |
|---|---|---|
| **Конфигурация** | AGENTS.md / CLAUDE.md / steering | Стабильные команды, границы, конвенции |
| **JIT-извлечение** | MCP-серверы, поиск по символам | Изменяющиеся факты: деплои, инциденты, тикеты |
| **Внешняя память** | Файловая система + структурированные заметки (Mem0, Zep) | Долгосрочные знания, история инцидентов |
| **Сессионная память** | TodoWrite, scratch pad, handoff-файлы | Состояние текущей задачи |
| **Сжатие** | Auto-compact (порог ~70%), `/compact` с фокусом | Выживание контекста в длинных сессиях |
| **Изоляция** | Sub-agents с ограниченным контекстом | Задачи с чёткими границами |

**Ключевые правила:**
- Изменяющиеся факты — только из живых источников (MCP/тулы), никогда копиями в файлах.
- Инструкции в файлах — для стабильного; всё, что меняется ежедневно, туда не принадлежит.
- При compaction: поведенческие правила должны быть записаны в постоянный файл **до**
  сжатия, а не после — иначе потеряются.
- CLAUDE.md как якорь compaction: агент записывает туда новые конвенции по мере обнаружения.

## 4. Иерархия для monorepo

```
AGENTS.md                    # корневые общие конвенции
packages/api/AGENTS.md       # оверрайды для пакета
packages/web/AGENTS.md
```
Инструменты резолвят ближайший файл к текущему контексту. Корневой файл — общие правила,
подкаталоговые — только отклонения.

## 5. Безопасность инструкционных файлов

- Ревьюить AGENTS.md в зависимостях так же строго, как код (prompt injection через файлы).
- «Должно всегда происходить» — в hooks/branch protection, а не в инструкциях
  (инструкции — подсказки, hooks — детерминированное принуждение).
- Изменения AGENTS.md — через PR с human approval; пинить в CI.
- Секреты — только env/vault, никогда в файлах инструкций.

## 6. Связь с SDD

| SDD-сущность | Роль в контексте |
|---|---|
| Конституция | Поведенческий контракт проекта (что агент обязан соблюдать) |
| Steering (Kiro) | Долгосрочный контекст: стек, стандарты |
| spec.md фичи | Контекст конкретной задачи (загружается на время фичи) |
| ADR | Решения, которые агент обязан учитывать при изменении границ |
| AGENTS.md | Точка входа: указатели на конституцию, ADR-индекс, спеки доменов |

Практика: в AGENTS.md — короткий указатель («перед изменением бронирования прочитай
решения в docs/adr/ по теме booking»), а не требование читать все документы.

## 7. Обслуживание

- Ревью файла ежеквартально, как CI-конфига.
- Удалять правила, которые агент выводит из кода сам.
- Следить за игнорируемыми правилами — признак перегруженности или противоречий.
- Устаревшие инструкции хуже отсутствующих: они кодируют устаревшее поведение как истину.
